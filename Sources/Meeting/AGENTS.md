# Meeting

The app-side adapter for the meeting feature. It keeps app UI, storage and STT ownership outside `TranscriptedCore` while reusing Core's transcription pipeline. This is the only module with full Core access, so the rest of the app reaches the pipeline through it.

## Module

`Meeting` in `.agents/modules.json`.

- **Owns:** live meeting capture through Core, the record / dismiss / remind prompt flow and ad-hoc call detection, imported audio, the transcription queue, failed meetings, meeting storage, transcript restyling, and the live transcript and dictation preview.
- **Public surface:** `MeetingSessionController` and `MeetingSessionState`, `MeetingPromptDetector`, `FailedMeetingStore` and `FailedMeetingItem`, `MeetingArtifact*`, `MeetingSTTAdapter`, `TranscriptionQueueCoordinator`, `MeetingStoragePaths`, `MeetingInviteeSuggestionPolicy`, `MissedCallNudgePreferences`, `SpeakerEmbedderFactory`.
- **May depend on:** Dictation, Speech, Support, Observability, and all of Core.
- **Entry points:** `TranscriptedApp.swift` wires `MeetingSessionController` and `MeetingPromptDetector`; `startRecording` / `stopRecording` in `MeetingSessionController.swift`.
- **Tests:** `bash run-tests.sh --filter Meeting`, `bash run-integration-smoke.sh`. Run `bash build-deps.sh --force` first after any change here.
- **Where to put things:** app-level meeting behavior goes in `MeetingSessionController`; anything reusable moves down into `Sources/TranscriptedCore/` (read its `AGENTS.md`). The UI side is `Sources/UI/Overlay/MeetingOverlayController.swift`, `Sources/UI/MenuBar/MenuBarPrimaryActionsView.swift` and `Sources/UI/Settings/TranscriptedSettingsView.swift`; check them after meeting changes.

## Flow

1. `TranscriptedApp.swift` wires `MeetingSessionController` into `MeetingOverlayController` (the meeting in the Notch island), the menubar, the meeting hotkey and the detected-call prompt (`CapturePillController`).
2. `MeetingPromptDetector` polls Calendar, watches supported apps, and ingests mic, audio-output and camera signals. When idle it asks `CapturePillController` for a short call prompt. `MeetingOverlayController` takes over after Record, and for active or finished recordings. Dismissals feed `MeetingPromptDetector.snooze(...)`, which uses `MeetingPromptHeuristics`.
3. `TranscriptedAppState` warms dictation at launch. Meeting diarization stays lazy until a meeting starts or audio is imported. `MeetingWarmupStatusPolicy` turns both into the progress copy the overlay, menubar and Settings share.
4. `startRecording` first runs `MeetingRecordingStartGate`, so a missing mic permission blocks before capture. System Audio Recording is read from macOS (`TranscriptedPermissionAccess.refreshSystemAudioRecordingStatusFromSystem`); when it is off, `systemAudioAccessPrompter` answers (`MeetingSystemAudioAccessFlow` decides). See "Mic only" below. Then `MeetingCaptureBridge` starts Core audio capture into app-owned scratch paths, after applying `MeetingMicrophonePreferences` (automatic Bluetooth isolation by default, macOS-selected input on opt-in; Core snapshots it per recording).
5. `MeetingAudioInactivityDetector` raises a warning after sustained silence so the overlay can ask whether the recording is still needed.
6. `stopRecording` awaits the mic and system files from the bridge, then starts transcription or queues it behind the active job. `cancelRecording` is only for confirmed discard: it stops capture, removes scratch audio and enqueues nothing.
7. `importAudioFile` routes standalone recordings through `MeetingImportedAudioPreparer` into the same save / naming / restyle pipeline. Imported jobs use their journal UUID as the transcript UUID. Recovery skips a live lease owner and rejects non-regular scratch entries. Cleanup-pending records delete scratch; committed or stable-transcript records with uncertain cleanup move audio to the visible failed queue; only records with no commit proof replay transcription.
8. `TranscriptionTaskManager` runs one diarize, transcribe, save pipeline at a time. When `LocalSpeakerPreferences` is on, queued meeting work also diarizes the local mic channel instead of treating it as one "You".
9. A subscription on `taskManager.$lastSavedTranscriptURL` runs `MeetingTranscriptStyler.restyleTranscript(...)` on a serialized background task (it rewrites the whole transcript and can rename artifacts, so it stays off the main actor), then hops back to update recent-meetings state. The restyle fails closed when a body has text the entry parser can't read, instead of replacing it with the empty placeholder.
10. After save, `MeetingAudioStorageManager` compresses retained WAV to M4A and applies the retention setting. Launch and Settings changes backfill existing meetings. Failed-meeting audio is compressed only after the failed queue points at the converted files.
11. Failed meetings can be played, revealed, retried or deleted from Home. `FailedMeetingStore` keeps retry state, `MeetingFailureKind` the categories, `MeetingFailureCopy` the wording. In speaker review, several local speakers can be named or collapsed back to one "You" ("Keep as You").

### Mic only

- First time system audio is off: the macOS allow box (Don't Allow records mic only, no second question). After an earlier denial the meeting starts mic only and the island asks about call audio while it records (`MeetingCallAudioAsk`, one ask per meeting, dropped if that start never records). The old pre-start two-button alert is deleted; `MeetingMicOnlyChoicePreference` only remembers the choice when the prompter doesn't ask while recording.
- A mic-only start (`MeetingRecordingStartDecision.capturesSystemAudio == false`) sets `Audio.capturesSystemAudio = false`: Core never builds the system tap, so macOS isn't asked again right after a decline, and the start waits only on the mic.
- At stop, `MicOnlySilentSystemTrack` writes a sparse silent system WAV at the mic's sample rate and length, so speaker review, Home re-transcribe and failed-meeting retries still see two tracks. The rate must match: Home's playback mix takes its rate from the system track.
- The health is marked `systemAudioSkippedByChoice`: the saved Markdown gets `mic_only: true` (no capture grade, kept through retry and re-transcribe), `sources` lists only the mic, and telemetry says `mic_only_by_choice`. Every failed-queue path keeps it as `FailedTranscription.micOnlyByChoice`; a retry writes the silent track if missing and saves with the marker instead of `system_audio_missing`.
- `micOnlyNotice` shows a quiet "Mic only" note on the pill (never a prompt, never blocks resting). Clicking it runs `turnOnCallAudioFromMicOnlyNotice()`, which re-reads macOS every 2 s until access is on or recording ends. The current recording stays mic only either way.
- "Turn It On" with no macOS answer keeps the tap, since it can still raise the box, and uses the permission-dialog timeout.

## Invariants

**Structure and ownership**
- `TranscriptedCore` owns the reusable pipeline. Prefer adapters and protocol seams over Core edits.
- `MeetingSTTAdapter.cleanup()` only clears the prepared meeting model. `TranscriptedAppState` owns STT engine lifecycle.
- `MeetingSessionController` has single writers for state: `transition(to:reason:)` and `updateDisplayStatus` in `+State.swift`, with legal moves in `MeetingSessionStateMachine`. Don't write state anywhere else.
- `TranscriptionTaskManager` stays single-flight. App-level queueing belongs in `TranscriptionQueueCoordinator`, not ad hoc background tasks.
- Failed-meeting queue, persistence and retry bookkeeping belongs in `FailedMeetingStore`, which gets its managers plus narrow weak callbacks and must not regain a controller back-reference. `TranscriptionQueueCoordinator` still reaches into the controller for queue-owned transitions. `FailedMeetingItem`, `QueuedTranscriptionJob` and `BackgroundTranscriptionWorkSnapshot` stay resolvable as typealiases on the controller. Keep `FailedMeetingItem.swift`, `FailedMeetingPresentation.swift`, `FailedMeetingUsableAudio.swift` and the other Foundation-only policy files free of `@MainActor`, `TranscriptedCore`, and store or controller references; the fast-test runner compiles them alone.
- `MeetingCaptureBridge` gets mic PCM behind Core's single bounded serial handoff, never on the capture callback. `MeetingMicPCMRelay` is only a synchronous handler switch; no second queue that could duplicate memory or coalesce admitted speech.
- Canonical homes, so don't duplicate the logic: `MeetingRecordingStartGate` (permission policy and reasons), `MeetingMicBoostPromptPolicy` (Boost Mic prompt), `MeetingFailureKind` (failure categories), `MeetingFailureCopy` (failure wording), `MeetingSessionUIPolicy` (whether background work keeps the island in transcribing/saving; speaker review alone must not).

**Storage and artifacts**
- Captures follow the current capture library; databases, logs and temp recordings stay under the app-owned Application Support folders. Imported audio is copied into scratch before transcription.
- Background work that moves saved artifacts (restyle rename, WAV to M4A recompression, retention pruning) must signal `CaptureLibraryChangeBroadcaster` (`Sources/Support/`) so Home re-resolves cached URLs. Consumers: `Sources/UI/Shared/HomeCaptureRefreshObserver.swift`, `OwnFileResolver.swift`.
- Retained-audio maintenance touches only Transcripted meeting transcripts and app-owned audio names. A transcript is storage-owned only with `capture_type: meeting` and a valid `capture_id` or `transcript_id`. Be conservative: Markdown stays, unrelated files stay, symlinked audio folders are ignored, converted or pre-existing M4A files are owner-only.
- Before deleting a WAV or promoting failed-queue audio to M4A, check duration within fixed codec-padding tolerance, channel count, and a decodable tail. Non-empty audio is not proof; a failed check keeps the WAV.
- Restyling preserves unknown frontmatter and old trailing Markdown sections.
- Artifact renames are journaled (`MeetingArtifactRecoveryStore`, `MeetingArtifactRenameTransaction`) before either file moves. Unresolved records block retries across launches and clear only when the pair is coherent. Home title edit and the post-save restyle share `MeetingArtifactRenamer`.
- No meeting is transcribed against a voiceprint database that saved people are still moving into. Every speaker-database writer awaits `MeetingSessionController.voiceprintMigrationGate`: queued live and imported jobs (`TranscriptionQueueCoordinator.prepareAndStartQueuedTranscription`, still "getting ready"), failed retries and saved-audio re-transcription (both re-check for other work after the wait), and Settings > Speakers rename/merge/delete/naming. Waiting never fails a job; a failed move opens the gate and retries next launch. A new speaker-database writer must wait on it too.

**Recording, cancel and failure**
- Discard deletes captured audio, so it must be explicit, visible and confirmed. Never wire Escape to it.
- Cancelling transcription never deletes a recorded meeting's audio: queued, preparing and running recorded jobs become "Transcription cancelled" retry rows (`TranscriptionTaskManager.cancelAll(recordedAudioRetryMessage:)`). Only an import's scratch copy is removed; the user's original is untouched.
- If a live stop has mic audio but no system file, continue the mic-only pipeline: label `system_audio_missing`, keep the mic audio beside the transcript, don't turn it into a failed-queue item. Exception: a mic-only-by-choice meeting whose silent stand-in couldn't be written keeps its grade and saves `mic_only: true`.
- Retry availability is two questions, both answered before the action is withdrawn. `FailedTranscription.isRetryable` asks whether the failure kind leaves anything to recover (single-source failures do, so does `noSpeechDetected`; `recordingTooShort` doesn't). `FailedRecordingSignalProbe` asks whether the surviving files hold signal. Never hide retry on an unproven verdict: `FailedMeetingUsableAudio.unknown` stays optimistic, since hiding it strands recoverable audio.
- Accidental start: files under 2 s from a session under `accidentalStartMaximumSessionForShortFiles` (4 s) with clean health, or `noSpeechDetected` with files and the controller's `sessionLength` (Record to Stop) under `TranscriptionTaskManager.accidentalStartMaximumLength` (10 s), clean health and no speech-like modulation. Core deletes scratch audio and journal, keeps no failed row, and publishes `DisplayStatus.discardedAccidentalStart`. The controller settles it as `.discarded`, a cancel: no "Saved" flash, no error, `meeting_transcript_skipped` with `failure_kind=accidental_start`. Short files from a longer or unhealthy session are a broken capture and stay a visible failure. Imports, retries and unknown lengths never take this path.
- Boost Mic: `MeetingMicBoostPromptPolicy` must not present or apply anything once stop, cancel or termination teardown begins. A call app merely open at start doesn't block the prompt; one launched during the meeting does. `MeetingCaptureBridge.armVoiceProcessingForActiveRecording` refuses while a call app holds the mic, waits out a mic recovery instead of dropping the boost, and watches an app it looked past. A boost that never applied (including one still retrying at Stop) is recorded `shown`, not `accepted`, so the Home hint stays. A "can't hear the call" report still open at Stop degrades the saved meeting only if the loss was confirmed, an earlier cause already degraded it, or it lasted `unresolvedUnheardDegradeSeconds`.

**Live system-audio warnings** (recording-scoped)
- A hard tap interruption goes through `CoreAudioSystemAudioCapture`'s bounded recovery (`SCKAudioCapture` is the legacy backend). Prolonged silence only raises a warning, because silence can be legitimate. Keep the warning latched in the overlay through transient unknown status until the meeting ends.
- Only an interruption or failure warning marks saved capture health degraded. A silence warning must not: it once stamped about 77% of production meetings `degraded`. Silence stays visible in `system_status` in the pipeline diagnostics snapshot.
- Exception `unheardPlayback`: Core heard only digital silence for a sustained stretch, after its own reconnects, while another app kept playing. Probably a lost call, so it has its own prompt and degrades the capture while it lasts. If the tap then hears signal, the prompt goes away and nothing is degraded (unless an earlier interruption already did). Only signal that needed a new tap or output (`systemAudioDidLosePlayback`) moves to "Call audio is back" and keeps the degrade.
- Recovered notices ("reconnected", "restored", "call audio is back") show only OK and auto-hide after `MeetingSystemAudioPromptPolicy.recoveredAutoHideSeconds` through the normal acknowledgement, so the degraded mark stays. Copy says call audio "may be missing", never "marked degraded".
- "System audio not verified" shows only when macOS doesn't confirm System Audio Recording is on. With access confirmed, a silent tap is a quiet Mac, usually in person.
- The inactivity warning owns prompt precedence because it can auto-stop. Keep system degradation icon-visible while inactivity is active, then show its prompt after inactivity clears if still relevant.

**Detection and prompts** (spec: `docs/auto-call-detection-spec.md`)
- Prompts come from upcoming calendar events, recently active supported apps, or a process holding the mic. Zoom and Teams need stronger calendar evidence: app open or frontmost proves nothing.
- Ad-hoc detection (`MicActivityMonitor` to `MeetingPromptDetector.updateMicInputUsers`) never prompts while Transcripted holds the mic: gated by `isOwnCaptureActive` (meeting or dictation), and the monitor drops our own bundle ID by prefix. Browser calls map to `.googleMeet` by family prefix, since helper processes hold the mic (`com.google.Chrome.helper`, `com.apple.WebKit.GPU`), and reuse `.runtimeApp`. Behind `AutoCallDetectionPreferences` (default on).
- A browser on the mic is not proof of a call (ChatGPT voice, web dictation, Loom, voice search; the browser prompt was turned down 2.4 times per recording in the 30 days to 2026-09-23). `MeetingPromptDetector.adHocCandidate` runs every browser signal through `BrowserCallEvidence`, with titles read off the main actor (the first read of a session holds the prompt until it lands). A call-only title prompts at once under its real provider (a Teams tab is `.teams`, id `mic:teams`; `Candidate.callEvidence == .tabTitle`) and sticks for the session. A focused known non-call site holds the prompt while in front, and if it was in front within 10 s of the browser taking the mic it sticks as `not_a_call` for that browser session, even after a tab switch, feeding neither the funnel event nor the missed-call nudge. Call apps are checked before non-call words, markers match whole words, and mail/calendar titles only count for a leading Meet code. A focused call app waits 20 s as `mic:browser-call`; anything else waits for continuous mic use (20 s if the same browser plays audio or the camera is on, 60 s otherwise) as `mic:browser`. A browser that lets go of the mic keeps its session for 30 s (Safari mutes that way). The camera only corroborates. Keep the generic, call-site and named ids apart so a Not now to one doesn't snooze the others, and keep every dismissal that couldn't name its call (`MeetingPromptCallEvidence.quietsProviderOnDismiss == false`) off the provider-wide `runtimeSuppressedUntil`. The re-check timer stops once a browser prompt was produced or held back, and `evaluate()` shows nothing while a session's first title read runs. Browser families compare as app families (`com.apple.WebKit` is Safari).
- Titles are read through the Accessibility permission the app already holds, classified in memory and dropped: never logged or sent. A learned-off decision only applies when titles were readable.
- Explicit Not now on an ad-hoc prompt feeds `MeetingPromptLearnedBackoff` (persisted only when the detector gets `learnedBackoffDefaults`, which `TranscriptedApp` passes as `.standard`; tests stay in memory) and marks that kind declined for the rest of the call, capped at 8 h. A Not now to any browser prompt declines every browser kind for that call. A recording during a detected call (prompt, menu or hotkey) counts as a yes only for kinds that call raised or held back; one started before any prompt teaches nothing. A prompt held back by learning also skips the missed-call nudge. Turning auto call detection off and on clears everything learned.
- Camera signal (`CameraActivityMonitor` to `updateCameraInUse`): same toggle. CoreMediaIO has no per-process attribution, so it is attributed via `MeetingPromptProvider.cameraCallProvider(forFrontmostBundleID:)`, frontmost browser or conferencing app only, so a Photo Booth selfie stays quiet. Audio-output signal (`MicActivityMonitor.onOutputChange` to `updateAudioOutputUsers`): same toggle and own-capture gate, for listen-only or hard-muted joins. Native conferencing families only (`MeetingPromptProvider.audioOutputProvider`); browser output never prompts alone. `MeetingPromptDetector.callSignals` merges them by candidate id (`mic:<provider>`): mic wins outright, output beats camera (real process attribution), so one call never double-prompts.
- Both monitors confirm through `SustainedActivityConfirmer` before emitting; keep that sustain gate when changing monitor timing. `MicActivityMonitor.shouldProbe` limits scans to provider-mappable bundles; widen it if a consumer needs more.
- Prompt timing: ad-hoc prompts keep a 60 s countdown (`MeetingPromptHeuristics.promptTimeoutSeconds`), calendar prompts the 30 s default. An unattended countdown is not a dismissal: expiry goes `CapturePillController.onExpired` to `MeetingPromptDetector.expire(candidate:)`, which re-offers after `promptExpiryReofferInterval` with no provider-wide suppression, capped at `maxPromptExpiryReoffers`; past the cap it inherits normal `dismiss` backoff. Explicit dismissals keep long provider-level suppression: runtime-only prompts remind sooner, calendar-linked ones wait for the next relevant window, Teams gets a longer minimum.
- Missed-call nudge (`onUnrecordedCallEnded` to `MeetingOverlayController.presentMissedCallNudge`) is awareness-only: it fires when a detected call (assembled across `evaluate()` passes) ends unrecorded. `MissedCallNudgePolicy` is the gate: long calls only, never after an explicit dismissal, never when a meeting recording overlapped, cooldown-limited. `MissedCallNudgePreferences` (default on) is written only by the nudge's "Don't show again"; there is no Settings toggle. It must never offer to record, since the call is over.
- Telemetry: `MeetingPromptCallTelemetry` plus `onDetectedCallEnded` emit one `meeting_detected_call_ended` per detected call (1 min or longer), the capture-rate denominator. Prompt events carry the `MeetingPromptSignalSnapshot` booleans and `dismiss_streak_bucket`. Bucketed enums only: never raw durations, bundle IDs or device names.
- Local mic diarization is opt-in (`LocalSpeakerPreferences`); by default the mic side stays one "You".

**Live transcript and dictation preview**
- Live transcript is Settings > General "Live transcript", off by default. Text is provisional and never reaches disk, logs or telemetry; the saved meeting is transcribed again after Stop.
- The dictation hover preview is on by default. `TRANSCRIPTED_DICTATION_PREVIEW=off` disables it and `alternate` streams every other take. It never runs under `AutomatedLaunchEnvironment` or during a meeting.
- The Foundation-only `LiveMeetingCaptionTrack` owns the sequencing. It closes a turn at the end-of-utterance token (`eouDebounceMs: 0`; FluidAudio's 1.28 s default skipped every chunk in that window, losing speech that resumed after a short pause) and pushes about 630 ms of silence through before each reset, one encoder shift at a time with yield and cancellation checks, so the buffered tail is decoded before its ordered commit. `LiveMeetingCaptionTrackTests` uses a held fake recognizer, never live models or audio.
- The live path adds nothing to the audio engine: it reads 16 kHz audio from the same live-PCM tap as the agent preview. Drain loops run at utility priority and pause while a dictation runs.

## Storage

- Capture library: `<capture-library>/meetings/*.md` and `audio/*_audio/` retained audio, WAV compressed to M4A after save. Retention cleanup uses the transcript's frontmatter date, not edit time. Backfill skips orphaned, non-Transcripted and symlinked folders. Failed audio is compressed only while the failed-meeting queue references it.
- State, under `~/Library/Application Support/Transcripted/state/`: `speakers.sqlite`, `stats.sqlite`, `failed_transcriptions.json`, and `imported_transcription_queue/import-job-*.json` crash-recovery journals for imports waiting behind another transcript.
- Scratch, under `.../tmp/recordings/`: raw captures, imported copies, `speaker_clips/`.
- Successful live and imported recordings are retained in the capture library before scratch cleanup. Failed live ones also copy their audio there while scratch stays for retry. Explicit discard removes scratch and saves nothing.
- Core logging for the meeting pipeline goes to `.../logs/` (`docs/observability.md`). Full map: `docs/storage-paths.md`.

## Files

Grouped by job. Several more are small and named for what they do.

**Session and lifecycle**
- `MeetingSessionController.swift` — recording lifecycle: `startRecording`, `stopRecording`, unexpected capture stop, stop snapshot and signal verification. The rest is in extensions: `+State` (declares the class, stored state, init, the single writers), `+Types`, `+RecordingStart` (start-permission decision, system-audio access, shared dictation mic relay), `+CancelAndTermination`, `+MicBoost`, `+LiveCaptureWarnings`, `+ModelWarmup`, `+TranscriptionRequests` (imports, re-transcription, cancel), `+Subscriptions` (Combine wiring, background restyle), `+TranscriptionOutcomes` (job start, failure, queue settle, accidental-start discard), `+Telemetry`, `+FailedMeetings`, `+LiveTranscript`.
- `MeetingSessionState.swift` — the state enum (`idle`, `loadingModels`, `ready`, `startingRecording`, `recording`, `stoppingRecording`, `transcribing`, `error`); `MeetingSessionController.State` aliases it.
- `MeetingSessionStateMachine.swift` — legal-transition table and queries (`isCaptureSessionActive`, `isSteadyStateRecording`, `mayReportUnrelatedFailureAsError`), plus `MeetingTerminalTranscriptionOutcome` and where the queue settles.
- `MeetingStopSequence.swift` — Foundation-only stop ordering, run against `MeetingCaptureControlling` so tests use a fake capture. An unexpected stop leaves `.recording` before any await, drains the shared PCM relay and resumes dictation. A finished stop fires exactly one terminal. `MeetingCaptureHealthEvidence` reads system-audio signal, tail failure and typed denial from the capture.
- `MeetingSessionUIPolicy.swift`, `MeetingWarmupStatusPolicy.swift`, `MeetingPipelinePhaseCadence.swift` (logs a transcribing phase on entry, then per new quarter of raw progress), `MeetingStartFailureClassifier.swift`.
- `TranscriptionQueueCoordinator.swift` — queue and dispatch bookkeeping; drives controller transitions by callback.
- `MeetingTranscriptionRequestBuilder.swift` — the one place every transcription entry point (re-transcribe, live queue, failed-row fallback) picks up People-in-the-room. Preference injected (default `LocalSpeakerPreferences.isEnabled`); queued rows keep their enqueue snapshot, imports never split. Tests: `Tests/MeetingTranscriptionEntryPointTests.swift`.
- `MeetingSTTAdapter.swift` — adapts the shared `STTRouter` to Core's `SpeechToTextEngine` and adds each call to the job's `MeetingPipelineTimings`. `MeetingProcessingTelemetry.swift` turns those into `meeting_transcript_saved` speed properties.
- `MeetingModelDownloader.swift` — loads the selected STT and diarization models together.

**Detection and prompts**
- `MeetingPromptDetector.swift` (state, init, polling, calendar snapshot cache) with `+Backoff`, `+CalendarRuntime`, `+AdHocCalls`, `+BrowserEvidence`. `MeetingPromptCalendarReader.swift` (background-queue `EKEventStore` reader).
- `MeetingPromptHeuristics.swift` (scoring, reasons, provider mapping, backoff rules), `MeetingPromptLearnedBackoff.swift` (kinds `native:<provider>`, `browser_verified`, `browser_call_site`, `browser_camera`, `browser_unverified`; quiet schedule 30 m, 2 h, 8 h, and a day for unrecognized browser mic; an unrecognized browser mic turned down 3 times with no recording in 30 days stops prompting until the streak is forgotten after 14 days), `MeetingPromptRecordAction.swift` (owns the async start so dismissing the panel can't cancel a start the user chose), `MeetingPromptTelemetry.swift`.

- `MeetingInviteeCalendarReader.swift` + `MeetingInviteeSuggestionPolicy.swift` — calendar-invite name suggestions in speaker review. Only the event whose start lines up with the recording start counts, in the same window as the record pop-up. Never asks for calendar access, never logs names, no raw emails, suggestions only: it never changes silent auto-naming.
- `MissedCallNudgePreferences.swift`.

**Failed, imports, storage**

- `MeetingStoragePaths.swift`, `MeetingAudioStorageManager.swift`, `MeetingTranscriptStyler.swift`, `MeetingArtifactRenamer.swift` (builds the `YYYY-MM-dd <title>` stem; also handles the retained `audio/<stem>_audio/` folder and the legacy `<stem>.summary.md` sidecar left by the removed local AI summarizer), `MeetingArtifactRecoveryStore.swift`, `MeetingArtifactRenameTransaction.swift`.
- `MeetingQuickSummaryExtractor.swift` / `MeetingQuickSummaryWriter.swift` — always-on heuristic extraction (decisions, action items, open questions, summary; no AI model) written to `auto_summary_*` frontmatter, so the MCP rollup tools (`list_action_items`, `list_decisions`, `digest`) cover every new meeting.

**Speakers**
- `MeetingSpeakerSeparation.swift` picks call-channel separation (`SpeakerSeparationOptions.tuned`) from the backend, the voiceprint model and the invite size. `MeetingSpeakerSeparationProvider.swift` reads the diarizer's `activeBackend` when each meeting runs (pyannote after a Nemotron load failure), never the one asked for at launch.
- `SpeakerEmbedderFactory.swift` resolves the voiceprint model at the app layer so `Bundle.main` and filesystem lookups stay out of Core. It never loads a model (the controller is built on the main actor at launch): the choice comes from model-file presence, and Core's `BackgroundLoadedSpeakerSegmentEmbedder` loads it when diarizer warmup, a meeting or the migration first waits. ReDimNet2 resolves from `Contents/Resources/redimnet2-voiceprint/Model.mlmodelc` in the bundle, else the `FluidAudio/Models/redimnet2-b4-slim` cache; one resolution per process. A missing model, or one that failed to load on this build, falls back to WeSpeaker and `speakers.sqlite`.
- `SpeakerEmbedderLoadFailureMemory.swift` — remembers a failed voiceprint load per app build and macOS version, so the next launch picks WeSpeaker; a new build or macOS update retries.
- `MeetingVoiceprintMigrationLaunch.swift` — at launch, when the chosen model carries saved people (ReDimNet2, not ERes2Net) and `state/speakers.sqlite` exists, starts Core's `SpeakerVoiceprintMigration` into `speakers_<id>.sqlite` through `voiceprintMigrationGate`. The gate closes at once; the run waits for the model's background load, and a failed load opens it with `embedder_unavailable` writing nothing. `speakers.sqlite` is only read.

**Live transcript and companion**
- `LiveMeetingCaptions.swift`, `LiveMeetingCaptionTrack.swift`, `LiveMeetingCaptionTrackSet.swift` (mic-only recordings never construct a system recognizer), `LiveMeetingCaptionRecognizer.swift` (FluidAudio `StreamingEouAsrManager`, Parakeet EOU 120M, 320 ms shifts), `LiveMeetingCaptionLog.swift` (about 8 hours, 1M characters), `LiveMeetingCaptionSampleQueue.swift` — the island's live transcript. One recognizer per actual capture track, built fresh per meeting and never while the setting is off. Stop waits for an in-flight load before freeing models.
- `LiveDictationCaptions.swift` / `LiveDictationPreview.swift` — the dictation hover's live words: one `LiveMeetingCaptionTrack` for the app session, loaded at least 8 s after launch and only once the dictation model is loaded and nothing is being dictated, `pause()`d between takes. A new take (by `dictationRecordingIdentity`, so device recovery keeps its words) attaches a `DictationPreviewSampleSink`; feeding stops at key-up (`releaseRequested`); the next take's feeding and reset wait while `isTranscribing`, so the final pass shares the Neural Engine with at most one chunk. `LiveTranscriptPrewarmPolicy.swift` — never compile a second EOU copy alongside the dictation model's compile or a take, never wait forever.
- `LiveMeetingTranscriptService.swift` + `LiveMeetingTranscriptState.swift` — provisional text for the companion and agent preview, started only by explicit per-session sharing; the final pipeline still transcribes independently. `CompanionConnectionService.swift` — the app-side companion socket owner: socket I/O on a utility queue, every permission decision and capture action on the main actor.
