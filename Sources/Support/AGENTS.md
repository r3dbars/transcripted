# Support

Module `Support` in `.agents/modules.json` (also `Sources/Accessibility/` and `Sources/Reliability/`, which have their own docs). App-wide helpers that don't belong to one UI or pipeline surface: persisted preferences, constants, permission access, storage paths, paste-back, launch and quit sequencing, the companion socket. It may depend only on Core `core-vocab`, so it can't name Meeting, Speech, UI or Observability types. Two grandfathered crossings are listed in `Sources/AGENTS.md`.

## Rules

- **Preference keys and notification names live here**, so UI and controllers don't drift. Keep a key and its notification stable across releases so upgrades keep the setting (Dock toggle, retention, etc.).
- **Naming traps.** `CaptureLibrary*.swift` (`CaptureLibraryChangeBroadcaster`, `CaptureLibraryMigrationPlanner`, `CaptureLibrarySize`, `CaptureLibraryPathSafety`) is the user-relocatable library of saved Markdown and audio, not `Sources/Capture/` (hotkeys and triggers). `ModelCacheInventory.swift` lives here but inventories `Sources/Speech/` STT model caches (Parakeet, Whisper), so check it first for Speech cache work.
- **`CaptureLibraryPathSafety.swift` is a synced copy.** The same byte-identical file (a real file, not a symlink, because a `core.symlinks=false` checkout would break one) also lives at `Sources/TranscriptedCore/Services/CaptureLibraryPathSafety.swift` and `Tools/TranscriptedCaptureKit/Sources/TranscriptedCaptureKit/CaptureLibraryPathSafety.swift`. Edit all three; `Tests/CaptureLibraryPathSafetySyncTests.swift` fails if they diverge. It is the one save-path safety rule (system directories rejected, home-directory escape hatch) used by `RecordingValidator.validateSavePath`, `CaptureLibraryResolver.validatedConfiguredDirectory` and `TranscriptedStoragePreferences.isSafeCaptureLibraryURL`.
- **Permissions go through `TranscriptedPermissionAccess` + `TranscriptedPermissionKind`.** UI must not duplicate TCC branching, metadata or copy. Meetings need only the narrow `systemAudioRecording` tier and never request full Screen Recording. Full Screen Recording is Writing's autocomplete only, and Writing owns that grant, so it is deliberately not a `TranscriptedPermissionKind` case (one would add a Screen Recording row to onboarding and Settings for everyone).
- **`PermissionsOnboardingPreferences` is the one completion flag** for the first-run flow. Keep onboarding state out of view-local storage so forced reruns stay consistent.
- **Storage paths:** `TranscriptedStoragePaths` is the app-side resolver. `Sources/TranscriptedCore/Services/CoreStoragePaths.swift` is the injected library-side seam. Map: `docs/storage-paths.md`.
- **Dictation triggers.** Dictation is one key (default Right Option) with a behavior (`DictationKeyBehavior` in `HotkeyPreferences`: hold or tap, hold only, tap to toggle). `PhysicalDictationTriggerPreferences` is the canonical binding layer. Don't add keycode logic or special-case right Option in UI or capture code. The Hands-Free and paste-last bindings and keys still exist in this file only for migration and `resetToDefaults`; nothing else reads them, and `migrateToOneDictationKeyIfNeeded` folds an old custom hands-free key into the one key as Tap to toggle. A missing macOS Fn setting counts as a conflict, because the macOS default is never Do Nothing.
- **Mic processing.** `MicrophoneProcessingPreferences` is the one switch: raw/off, default software AGC without playback ducking, or opt-in Apple voice processing (VPIO, which can duck other apps). The in-meeting Boost prompt and Home's "Boost mic next meeting" apply VPIO to one meeting only and never save the mode; `migrateBoostedVoiceProcessingIfNeeded` runs once at launch to undo Boosts saved by older builds and sets `micBoostHintsHiddenThrough` so answered hints stay gone. `CallAppMicrophoneSharingMonitor` sees Zoom, Teams, Webex and FaceTime by app presence only (never opens audio); while one is open at a recording's start, meetings and dictation stay on software AGC. Mid-meeting, the Boost prompt checks real mic use (`MicrophoneSharingPolicy.isCallAppUsingMicrophone`, fed by `MicActivityMonitor.currentMicInputBundleIDs()`), so a Teams window left open during a browser call doesn't block it.
- **`NSRunningApplication.bundleIdentifier` can block** on a synchronous LaunchServices call (froze the app 5+ s in 1.1.66, Sentry APPLE-MACOS-2Q). Read running apps through `RunningApplicationsReader` (one serial background queue); the monitor's pre-capture `refresh()` stays on main but hits warm caches.
- **`LaunchAtLoginController.applyStartupState` runs `SMAppService` calls on its status queue, never main.** A slow `status` reply froze launch (Sentry APPLE-MACOS-3W).
- **Retention and cleanup.** `AudioStoragePreferences` stores only the choices: meeting audio retention (`meeting-audio-delete-after`: 7 days, 30 days, never) and the separate `DictationAudioKeepWindow` (`dictation-audio-keep`: off, 7 days, 30 days, forever; default 30 days). Destructive cleanup belongs in `Sources/Meeting/MeetingAudioStorageManager.swift` and stays conservative: Settings asks before switching to a 7- or 30-day meeting cleanup window.
- **Quit confirmation is always on** (`QuitConfirmationPreferences`; the opt-out was removed in the 2026-08 settings simplification). Quitting during a live meeting stops capture. `AppTerminationSequence` orders async Quit cleanup: dictation first (if it can't promise its audio is saved, Quit is refused and nothing else shuts down), then the meeting, app state, the persistent dictation input, and the local event flush, all before AppKit hears `true`.
- **Single instance.** `SingleInstanceReopenPolicy` has deliberately no alert case: an app-modal alert can hide behind other windows and block Stop during capture, so a second launch always lands on real controls.
- **`UserDefaultsChangeOnlyWrites`**: every `UserDefaults` write posts `didChangeNotification`, even for the same value. Code that refreshes a cached flag on window activation or meeting start writes only real changes.
- **MCP config.** `ClaudeDesktopIntegrationInstaller` owns the `mcpServers` JSON merge (Claude Desktop and Cursor): preserve existing servers and back up invalid JSON rather than overwriting. It also refreshes the helper's owner-only `mcp-observability.plist`: copy only validated version/channel/revision values, and remove the file when anonymous analytics is off or the PostHog config is invalid. `AgentMCPConnector` is the seam for connecting agents (Claude Code via the `claude` CLI, Codex `~/.codex/config.toml`, Cursor `~/.cursor/mcp.json`, all pointing at the shared installed helper); a new agent gets a detect / isConnected / connect triple there, not bespoke UI logic. Never write `~/.claude.json` directly, because Claude Code's CLI owns it.
- **Companion socket.** `CompanionProtocol` and `CompanionSocketServer` are a small explicit control surface, reachable only by this user's processes. Parsing and logging never echo request text, credentials, paths or transcript content. Authentication belongs to one listener lifetime (`CompanionConnectionEpoch`): a queued request from a closed listener gains no authority.
- **Paste-back.** `ClipboardRestoringTextPaster` borrows the clipboard, posts a layout-aware Cmd+V and restores the user's clipboard; the details are in the next section.
- **Model choice.** `TranscriptionModelPreferences` is the shared model switch for dictation and meetings. Unknown stored values (including the retired Nemotron beta) fall back to the default. `parakeetUltraExperimental` maps to `ParakeetModelVariant.ultra`, a local-install-only variant that `ModelCacheInventory` resolves from `~/Library/Application Support/Transcripted/models/parakeet-ultra/parakeet-tdt-0.6b-v3` only when the install marker exists; `TranscriptionModelVisibilityPolicy` hides it until then (`scripts/models/parakeet-ultra/README.md`). Model-specific runtime behavior belongs in `Sources/Speech/` and `Sources/Meeting/`.
- **Speaker voiceprint.** `SpeakerEmbedderPreferences` stores the choice: ReDimNet2 (default, `Tools/SpeakerEvalHarness/VOICEPRINT_RESULTS.md`), the diarizer's WeSpeaker (previous default and fallback), or ERes2Net. There is no Settings switch ("Better matching on calls" was removed); a stored WeSpeaker reads as the default, and `TRANSCRIPTED_SPEAKER_EMBEDDER` overrides. Each model has its own DB (`speakers_<id>.sqlite`; WeSpeaker keeps `speakers.sqlite`). `DiarizationBackendPreferences` is a hidden Nemotron-vs-pyannote switch (`TRANSCRIPTED_DIARIZATION_BACKEND` or `diarization-backend-preference`, no UI), read once at meeting-controller init, so it applies on the next launch. Both share `speakers.sqlite`; only the lab-only `TRANSCRIPTED_NEMOTRON_EMBEDDER=online` routes to `speakers_wespeaker-fluid-online.sqlite` via `SpeakerEmbedderFactory`.
- **`SpeakerNameSelectionPolicy`** holds speaker search, "You" matching and duplicate-name disambiguation; keep that out of SwiftUI controls.
- **`CustomDictionaryPreferences` and `DictationAutoSendPreferences`** back the Settings General and Dictation pages. Change a parsing rule or threshold and update their tests. `CustomDictionaryTextProcessor.matcher(for:)` is also what `Sources/UI/Shared/DictionaryPastMeetingFix.swift` uses, so past and new fixes match the same way.

## Paste-back details (`ClipboardRestoringTextPaster`)

Split across `ClipboardPasteTarget.swift` (pasteboard seam, Cmd+V, target app), `ClipboardPasteOutcome.swift` (outcomes, timing, diagnostics), `FocusedTextPasteConfirmation.swift` (AX confirmation), `ClipboardPasteConfirmationWait.swift` (the wait and `ClipboardLateConfirmationWatch`), and the `+Pasteboard` and `+SavedClipboard` extensions.

- Local-only timing separates clipboard preparation, Cmd+V dispatch, target read and confirmation wait.
- Targets that expose no confirmation surface (common for Electron apps, which build no AX tree unless an assistive client asks) end the wait after a post-dispatch target read, since no confirmation can come. Auto Enter takes never end early.
- Targets that do expose one keep the full wait, except a dictation that won't press Auto Enter (`endWaitOnLikelyPaste`, from `DictationAutoSendRequestDecision.pasteMayEndWaitOnLikelyPaste`): a read that would make the paste `.likelyPasted` anyway (`FocusedTextPasteConfirmationPolicy.endsWaitOnLikelyPaste`) ends the wait. The restore delay gets the skipped wait added back (`likelyPasteRestoreDelay`) so the clipboard returns about when it would after a full wait. `ClipboardLateConfirmationWatch` keeps checking Accessibility off the blocking pump to the same deadline and moves the restore to the short confirmed-paste delay if the target confirms; that calls `paste(onLateConfirmation:)` with a `dictation_paste_late_confirmed` diagnostic, which the dictation controller logs and tracks (`target_confirmation_mode` plus the take's session id). A focus change or a newer paste stops the watch silently. Local `likely_paste_ended_wait` is true whenever a quick read ended the wait.
- When nothing confirmed but the target stayed frontmost and read the borrowed clipboard within `clipboardLikelyPasteReadWindow` of Cmd+V, the outcome is `.likelyPasted`: the overlay says "Pasted", the clipboard is restored after the longer fallback delay (the read isn't tied to a process, so a slower real reader must still get the text), telemetry reports `target_confirmation_mode=clipboard_read`, and Auto Enter still holds Return (`paste_unverified`).
- A quick read doesn't count when the focus plainly can't take text: a role in `FocusedTextPasteConfirmationPolicy.nonTextEntryRoles` (web page body, static text, link, image, button-like controls, menus, toolbar) with no settable value and no editable ancestor. Keep containers (cells, rows, tables, windows, groups, scroll areas) out of that set: selected spreadsheet cells and GPU terminals report them for real paste targets.
- The borrowed item carries the nspasteboard.org `TransientType` marker so clipboard managers skip it.
- Otherwise the text stays on the clipboard for a manual Cmd+V with neutral wording (a slow target may still paste, so the notice must not invite a double paste). The replaced clipboard is kept in the shared `clipboardSavedBeforeFallback` slot for up to `clipboardSavedBeforeFallbackMaxAge`; the next paste from any paster restores it if nothing else was copied meanwhile. A clipboard with an nspasteboard.org Concealed/Transient/AutoGenerated marker is never kept for later, and snapshots keep those empty markers so a restored password stays marked.
- A new paste first runs any other paster's still-waiting restore (unless that paster is mid-paste). `restorePendingClipboardsBeforeQuit()` runs them all from `applicationWillTerminate`.

## Files by group

- **Launch and lifecycle:** `AppLaunchSteps` (launch work as a list so tests check each step still runs), `AppTerminationSequence`, `AutomatedLaunchEnvironment` (the one check for "this launch is our own harness": build.sh launch smoke, launch benchmark, packaged first-run smoke; analytics, Sentry, setup resume, Sparkle and permission probes all skip real-user behavior), `SingleInstanceGuard`, `SingleInstanceReopenPolicy`, `ActivationPolicyController` (Dock toggle plus live-recording safety, so idle menu-bar-only still appears in the force-quit dialog during capture; keep activation-policy switching out of recorders and views), `LaunchAtLoginController` / `LaunchAtLoginPreferences` (explicit choice, one-time post-onboarding default-enable because meeting detection is dead while the app is closed, `LaunchAtLoginNoticePolicy`), `QuitConfirmationPreferences`, `TranscriptedAppVersion`, `TranscriptedConstants`.
- **Capture library:** `CaptureLibraryChangeBroadcaster` (debounced `.meetingCaptureArtifactsDidChange`; an empty id set means a library-wide change), `CaptureLibraryMigrationPlanner` (relocation: finds meeting Markdown, retained `audio/*_audio/` folders, dictation day files, kept dictation audio `dictations/audio/*.m4a|*.wav` except audio named by a day file left behind on a collision, and Writing day files `writing/*.md`; skips destination collisions; copy never deletes; move is copy, switch, then `removeOriginals` trashes each original only if unchanged since its copy by size, file count and newest mtime, and its copy still exists; `CaptureLibraryMoveSummary` is the status line), `CaptureLibrarySize` (once per launch, bucketed, so unbounded retained-audio growth shows in the event log), `CaptureLibraryPathSafety`, `TranscriptedStoragePaths`, `ModelCacheInventory`, `AudioImportQueue` (FIFO of files to transcribe; the app delegate feeds `MeetingSessionController.importAudioFile(from:)` one at a time, files added during recording wait until capture stops; also filters dropped URLs to audio/video), `CoalescedRefreshState` (one running read plus one pending refresh; never publish an older snapshot over a newer one).
- **Dictation preferences:** `HotkeyPreferences`, `PhysicalDictationTriggerPreferences`, `OnboardingDictationShortcutPolicy`, `DictationAutoSendPreferences`, `DictationCleanupPreferences` and `DictationFillerCleanupPolicy` (light filler removal), `DictationMufflePreferences` (opt-in low-pass on other apps' audio while dictating, off by default because it needs System Audio Recording access), `CustomDictionaryPreferences`, `AppSoundPlayer` (`UISoundPreferences` plus cue playback), `NotchIslandPreferences` (opt-in "Show island in screen sharing", off by default; on sets the panel's `sharingType` to `.readOnly`, so it shows in screenshots and recordings; the island is the only dictation, meeting and call-prompt window, and the old `dictationOverlayPresentationMode` value is ignored), `DictationPersistentInputPreferences` (faster-Bluetooth-dictation opt-in, preferred CoreAudio device UID and crash-recovery ownership marker; reads as off while the Mac mic recorder handles dictation, and `isStoredOn` is the raw toggle).
- **Microphone:** `MicrophoneChoicePreferences` (the one Settings "Microphone" choice: `automatic`, `device(uid:)`, `macOSInput`; used only while the Mac mic recorder is on; the UID is the one `DictationPersistentInputPreferences` stores; an older pick carries over once, only if Faster Bluetooth dictation was on), `PinnedMicrophoneCapturePreferences` (rollout switch, on by default since 1.1.63, for recording the chosen mic through a Core Audio IOProc on its device ID instead of an `AVAudioEngine` input node, which would open the macOS default input first and flip AirPods into call mode; opt out with `pinned-microphone-capture` false or `TRANSCRIPTED_PINNED_MIC_CAPTURE=0`; read at each start; Apple voice processing still uses `AVAudioEngine`), `MeetingMicrophonePreferences` (explicit use of the macOS-selected meeting input, default off to keep Bluetooth call isolation; read before each recording; `recordsMacOSInput` ignores it while the Mac mic recorder is on), `MicrophoneProcessingPreferences`, `CallAppMicrophoneSharingMonitor`, `ZoomMicrophoneSharingMonitor.swift` (only a typealias and `isZoomRunning` kept for old branches; delete once nothing uses them), `RunningApplicationsReader`.
- **Meetings and speakers:** `AutoCallDetectionPreferences` (default-on ad-hoc call detection via mic activity; gates `MicActivityMonitor` and the General "Auto-detect calls" setting; `docs/auto-call-detection-spec.md`), `LocalSpeakerPreferences` (split the local mic into multiple named speakers, or keep one "You" track), `TranscriptionLanguagePreferences` (meeting and import language, `auto` or a code, plus the effective code per model; callers snapshot it with their model so queued work is unaffected by later changes; dictation never reads it), `TranscriptionModelPreferences`, `ExistingInstallModelPrefetchPolicy` (when to prefetch Parakeet files after an update), `SpeakerEmbedderPreferences`, `DiarizationBackendPreferences`, `SpeakerNameSelectionPolicy`.
- **Permissions and agents:** `TranscriptedPermissionAccess`, `TranscriptedPermissionKind`, `PermissionsOnboardingPreferences`, `AgentMCPConnector`, `ClaudeDesktopIntegrationInstaller` (also bundles the read-only MCP helper, runs its self-test, and silently refreshes a stale installed helper at launch), `CompanionProtocol`, `CompanionSocketServer`, `AnalyticsPreferences` (the Settings toggle; `AnalyticsReporter` and `ClaudeDesktopIntegrationInstaller` read it), `DockVisibilityPreferences`.
