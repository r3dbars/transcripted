# Settings UI

`Sources/UI/Settings/` owns the main window (sidebar, Today, Meetings, Dictations, Writing, Speakers, Agent, and the combined settings page), first-run onboarding, Home, and speaker naming and review. The surface summary is `Sources/UI/AGENTS.md`; this file is the per-file guide.

## Module

`UISettings` in `.agents/modules.json`.

- **Public surface:** `TranscriptedSettingsWindowController`, `TranscriptedSettingsPage`, `PermissionsOnboardingView` and its window controller, `SpeakerNamingSheet`, `HomeView`, the `Pages/` views.
- **May depend on:** UIShared, UIOverlay, AppState, WritingBridge, WritingRuntime, Meeting, Dictation, Speech, Support, Observability, Core `core-vocab`. Only AppShell and UIMenuBar may depend on it.
- **Speaker persistence:** Settings reaches database edits, migration status, saved merge history and naming metadata through Meeting-owned `SpeakerSettingsStore`, `SpeakerSettingsMigration` and `SpeakerNamingMetadata`. Keep Core engine types behind those seams; presentation and edit completion stay in this directory.
- **Start at:** `TranscriptedSettingsWindowController.swift` (opens the window), `TranscriptedSettingsView.swift` (the shell).
- **Tests:** `bash run-tests.sh --filter Home`, `--filter Settings`, `--filter Speaker`, `--filter UIAutomationSurfaceContract`.
- **Product surface to keep:** Speakers directory (review, rename, merge, delete), per-app Auto Enter, model-cache inspection and cleanup, retained-audio playback.

## Rules

- `TranscriptedSettingsView` stays the shell. New row or view helpers go in a focused sibling file; new pages go in `Pages/`.
- Views can own local `@State`, but runtime side effects go through injected bindings, controllers, preferences, or `TranscriptedSettingsActions`. Pages own local confirmation state only.
- Keep General-page row styling in `TranscriptedSettingsGeneralControls.swift` so editors stay aligned. Row explanations live in each row's ⓘ `GeneralInfo` popover, not in captions.
- Agent setup stays in `AgentConnectionSettingsPage.swift` and shares copy through `AgentConnectionGuide`; don't duplicate prompt text.
- No transcript parsing, speaker database work, or retained-audio cleanup here. Use `Sources/Meeting/`, `Sources/TranscriptedCore/`, or `Sources/UI/Shared/`.
- Writing views are driven by `WritingSettingsModel` in `Sources/Writing/`; runtime changes go through `WritingController`, never from a view.
- Run `python3 scripts/dev/check-source-pins.py --changed-only` before moving code; it resolves the current source-text assertions and their targets. Do not rely on a hand-kept list of pinned Settings files.
- Redraw gate: anything new the shell reads from `meetingSession` in its body must be added to `SettingsMeetingShellState.swift`, or the window won't redraw.
- A closed window does no I/O. Gate work for a window nobody can see on `navigation.isWindowOpen` (`SettingsClosedWindowPolicy.swift`).
- Per-mark work on Today runs once per snapshot, off main. Don't put it back in a view body.
- Privacy: no new analytics event from here beyond `settings_action_clicked` action ids. Today is local files only, no network.

## The shell

`TranscriptedSettingsView.swift` holds stored state, `init`, `body`, and the Home row actions (copy, re-transcribe, expansion, row menus, delete with undo). It still owns every Home side effect (delete, rename, copy, retranscribe, the shared root alert, undo staging, analytics). The rest are extensions:

- `+Pages.swift` - sidebar (six places, then Settings, Feedback and the version line, all update words from `UpdateStatusWords`), detail column, page routing, page hosts.
- `+Today.swift` - Today's host: its actions, the first-day key line, the setup checklist state and steps, and landing a Today dictation click on its entry.
- `+HomeMeetingActions.swift` - `RootAlert`, rename, failed meetings, `revealOwnFile`/`openOwnFile`, failure alerts.
- `+HomeSpeakerVoiceprints.swift` - a meeting's "Who spoke?" routing (`openWhoSpokeCard`: the queue's card when voices wait, else the transcript card) and the transcript naming persistence, including re-embed from retained audio for unlinked voices.
- `+GeneralEditors.swift` - the combined page, its Advanced section, and the injected `general*Editor` properties (voice model, speaker matching, Bluetooth mic, microphone, Auto-send, permissions, mic processing, privacy with Send diagnostics). It places `storagePage` (Library) and `aboutPage` (in Advanced) from `+Pages.swift`.
- `+AdvancedEditors.swift` - wires Settings › Advanced (`AdvancedSettingsSection` in `Pages/GeneralSettingsPage.swift`) and decides when the voice model moves up top (`generalModelNeedsAttention`).
- `+ShortcutEditor.swift` - the dictation key and Behavior (Dictation), the Meetings key (Meetings), and the Keyboard shortcuts switch (in Advanced while on; in place of the key rows while off). The one-time "Dictation moved to Right Option" note lives under the dictation key row.
- `+DictationMuffle.swift` - the "Muffle other audio" toggle; turning it on asks for System Audio Recording here, so dictation never prompts.
- `+Refresh.swift` - state refresh, analytics, model cache, launch at login.
- `+Preferences.swift` - corrections, capture library, Auto Enter, update actions.

The combined settings page is card-based: four visible groups (Dictation, Meetings, Library, Privacy; 15 rows) and exactly one disclosure, named Advanced, that holds every other setting (`SettingsAdvancedDisclosure`; whether it's open is remembered under `SettingsAdvancedExpanded`). No other setting hides behind a disclosure or a second page (ⓘ popovers and the System Audio "How to turn it on" help stay): rows that only matter while a switch is on (Auto-send's send key and apps) show under that switch, and Permissions and the voice model move above Dictation whenever they need attention, so the Home needs-attention links always land on a visible card. Keep the protected rows out of Advanced: Auto-send, Free up space (model-cache inspection and cleanup, with a Review… breakdown), Crash reports, Usage stats and Send diagnostics. Settings has one feedback row (Advanced › About › Feedback); the sidebar has the other, and Email support only appears under Send diagnostics after a send. The corrections editor opens as a sheet. All configuration is on that one scrolling page, reached from the sidebar's Settings row; there is no tab strip, and the old `.storage`/`.about`/`.models`/`.shortcuts`/`.privacy`/`.beta`/`.support` page cases are deleted. The UI smokes open Advanced (`transcripted.settings.advanced.toggle`) before looking for the import row and About.

### Today

`TodayPresentation.swift`, `TodayViewModel.swift`, `Pages/TodaySettingsPage.swift`, `TodayClockViews.swift`, `TodayWritingDayFileCache.swift`, `TodayFirstDay.swift`, `TodayLiveAndReveal.swift`, and the shell's `+Today.swift`.

- Data comes from local files only: `RecentMeetingsScanner.loadTodayIndex`, `DictationTranscriptStore.savedDictationDayCounts`, and `Writing_<date>.md` files (`TodayWritingParser`, cached by mtime+size).
- The rolling seven-day tape retitles the header and swaps numbers when you pick a day (`TodayTapeBuilder.dayStats`). Below it, the day splits into sessions (`TodaySessionBuilder`): a pause over 30 minutes starts a new one, titled by rule, never a model (first meeting's title, else the first dictation's opening words cut at a whole word, else "Writing in <app>"). Picking a session picks its latest mark and vice versa.
- Writing bar lengths are estimated from word count (the files keep only the first keystroke); a writing click opens its day file.
- Meeting clicks reuse `requestHomeRevealMeeting`; dictation clicks open Dictations and scroll to that entry (`requestDictationReveal`, loading older pages up to `TodayDictationRevealPolicy`). Stream colors are `LibraryTokens.meetingsStream`/`dictationStream`/`writingStream`.
- First day (nothing saved yet): no sentence, one line that teaches the person's own key and behavior (`TodayKeyHint`), Record a meeting with its shortcut. The setup checklist (calendar, an agent, a file: the three things setup no longer asks) sits at the bottom of Today on any day; each step drops out when done, and dismissing or finishing it retires it for good (`TodaySetupChecklistPreferences`, plain `UserDefaults` keys).
- The header sentence never swaps for a loading line: it keeps the last snapshot's numbers while a read runs, and only an empty stale snapshot holds a blank line instead of saying "nothing". Past days don't repeat the date on the card.
- A meeting recording now is a green bar on today's meetings lane (`TodayLiveMeetingMark`), fed by the shell's `SettingsRecordingClock`, so only that bar redraws, once a second, and only while recording.
- Performance: `TodayTapeDay` stores `allMarks` and `sessions`; each `TodayTapeMark` carries its `hoverText`; `TodayTapeSelection` resolves hovered/picked once per draw; only the Now label and tape marker sit in `TimelineView(.everyMinute)` (`TodayClockViews.swift`); `TodayClockPolicy.needsRollover` rebuilds the snapshot at midnight, wake, become-active, and window-key so the seven-day window and Today label roll over; the day card, week cells, and session rows are `Equatable` (session rows include `formatKey`) and do not take `now`. `today-page-wide-minute-tick` in `scripts/dev/lint.py` fails if the page-wide minute wrap or a `now:` on the page/card/row comes back.

- `SpeakerPeoplePrintSections.swift` / `SpeakerPeoplePersonRow.swift` - the list: "Named automatically · N" (full, glowing prints and a glowing dot per person), "Still learning" (partial prints), then "Not named yet" (unnamed voices outside the open card). The directory is plain `VStack`s, no `LazyVStack`: a title then its rows per section (18 pt between sections), every row laid out up front so the list's height is exact. Lazy layouts moved the scroll under the reader: a `LazyVStack` per section inside a `VStack` never settles on a long list (macOS 26 hangs mid-scroll, macOS 27 jumps back), and one `LazyVStack`, with `Section` headers or with the titles as plain items, still jumped back about 1,400 pt now and then on macOS 26.6. The cost is the first open: on a macOS 26.6.2 VM about 95 people lay out in 117-163 ms, 210 in 256-343 ms and 400 in 537-746 ms (the known ceiling; revisit if real lists get near 1 s). If the list ever needs to be lazy again, the smoke below has to pass 50+ runs at 100/40/6 and 150/60/6 on macOS 26 first. `bash scripts/dev/test-speakers-directory-scroll.sh` scrolls the real page at several sizes and fails on either.
