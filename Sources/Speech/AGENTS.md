# Speech

`Sources/Speech/` owns dictation STT and the dictation mic engine: `STTRouter`, `ParakeetEngine` and its extensions, Whisper and Apple Speech engines, the pinned-mic path, device monitoring, the shared meeting mic, the dictation muffle, and `DictationSession`. Meetings reuse the router through `Sources/Meeting/MeetingSTTAdapter.swift`. Persistence after the stop is `Sources/Dictation/AGENTS.md`.

## Module

`Speech` in `.agents/modules.json`.

- **Public surface:** `STTRouter`, `ParakeetEngine`, `PersistentDictationInputController`, `DefaultInputDeviceMonitor`, `SharedMeetingMic*`, `DictationSession` and its types, the start/stop policies in `DictationRecordingStartOverlayPolicy.swift`, `DictationTrigger` and `DictationHotkeyRouter`.
- **May depend on:** Support, Observability, Core `core-vocab`, and Core `mic-primitives` (`PinnedMicrophoneCapture*`, `MicrophoneDownmix`, `MacLidState`, `AudioTapInstallGuard`, `AudioInputTapTeardownPolicy`, `ModelDownloadService`).
- **Grandfathered crossings:** `DictationSession.swift` takes `TranscriptedAppState`; `ParakeetASRInference.swift` and `STTRouter.swift` name Core's `TimedTranscriptToken`. Fix by injecting narrow dependencies, or adding the token type to a Core tier.
- **Entry points:** `STTRouter.transcribe`, `ParakeetEngine` recording start/stop, `DictationSession`.
- **Tests:** `bash run-tests.sh --filter Parakeet`, `--filter STTRouter`, `--filter Dictation`. The real proof is `bash check.sh hardware`.

## Rules

- **AirPods, every PR.** State what happens with a Bluetooth headset as the default input, even if it's "unchanged, moved only". Starting a headset's input stream flips AirPods into call mode and the audio garbles. Policy tests are not physical AirPods proof.
- **Never write the Mac-wide default input per session** (`kAudioHardwarePropertyDefaultInputDevice`). Mic choice binds only the app's own AUHAL via `applyPreferredDictationInputDevice`. The old per-session write/restore caused the AirPods route flip-flop, a ~470 ms vs 83 ms start tax, and silently killed `PersistentDictationInputController`'s ownership (2026-08-24 audit). `Tests/BluetoothRouteContractTests.swift` pins it. The only legitimate writes are `PersistentDictationInputController`'s, through `DefaultInputDeviceMonitor.shared.setDefaultInputDevice(_:)` so they're self-suppressed.
- **Never register a fourth direct listener** on the default-input property. Subscribe to `DefaultInputDeviceMonitor`.
- **Idle readiness must not leave `AVAudioEngine` running** (the macOS mic indicator stays lit). Idle prewarm does the real AUHAL bind plus format readiness check, with no Bluetooth-fallback deferral.
- **Tap format comes from the live node** after voice processing is applied: hardware input format for raw input, VPIO's processed output format when active. Never `format: nil` and assume AirPods' 24 kHz converts to a stale 48 kHz bus (`-10868` on a macOS 27 repro). Each retained buffer keeps its own sample rate; final inference resamples each segment separately.
- **Every input selection must match the actual AUHAL binding** before readiness is published. Binding failures use bounded route settling, not graph churn.
- **Unknown input is not proof of readiness.** Default-input and engine-config notifications must dispatch recovery even if the CoreAudio route lookup times out: both lookups stay off the main actor behind separate two-worker circuits, and recovery gets an explicit unknown route.
- **Bounded CoreAudio work.** Timed `AVAudioEngine` work has a four-worker process-wide circuit; a lease is held until the call actually returns, even past its timeout. Retired native graphs have a four-entry delayed-release cap. When either is full, fail closed instead of replacing again. Timed-out system-input writes have a two-worker breaker: one blocked queue may be replaced once, then route work fails fast until a worker returns.
- **While the system-input circuit is open** (`circuitOpenError`), `startRecording` fails before the pinned path with no fallback, no graph rebuild, and the `audio_engine_work_circuit_open` error throttled to one per `audioStartFailureReportThrottle`. Without that, the readiness wait turned every 100 ms poll into a fallback, an engine rebuild, and a Sentry error (Sentry 3T/3V, 1.1.69).
- **Zombie-engine recovery** is its own generation-gated task; it replaces the stale engine through a timed reset and retries once. Don't fold it into the startup watchdog or reuse the zombie graph.
- **Recovery intent.** Recovery retains recording intent across notification bursts until the current generation finishes. Terminal interruption clears restart intent before publishing but keeps captured audio for explicit recovery; retained audio alone never restarts capture or carries into a fresh dictation.
- **Route analytics** commit only after the config-change debounce resolves to a new categorical route; churn and A -> B -> A stay quiet. Input lookups use one latest-wins mailbox. Idle route changes only mark readiness stale; native recovery runs during a recording or at the next start.
- **Threading.** `ParakeetEngine` is `@MainActor` for state, published UI state, and event reporting. All `AVAudioEngine` graph work runs on the serial queue held in `audioGraph`. Keep start/stop/readiness APIs async so the main actor never blocks on CoreAudio. Capture-queue math (levels, preview sink) touches no engine or `inputNode`.
- **Don't widen CoreAudio fences per start** by setting "fence in flight" properties on `ParakeetEngine`: a start suspends many times, so prewarm and recovery would read the widened values, and recovery restarts call `startRecording()` with defaults and silently drop back. A per-start fence must be a parameter threaded through `audioInputSnapshot` and `runTimedAudioEngineWork`, and only once a measurement says a stage needs it.
- **Don't move the Parakeet encoder to CPU + GPU.** Tried and rejected 2026-09-27 (M5 Max, cold 4 s take): idle GPU only ~5 ms faster (88 vs 93 ms), but with another app keeping the GPU busy 867 ms vs the Neural Engine's 61 ms. People dictate during video calls. `scripts/ops/dictation-stop-autoeval.sh --encoder-compute cpu-and-gpu|all` is the local-only comparison; production keeps FluidAudio's default unless `TRANSCRIPTED_PARAKEET_ENCODER_COMPUTE_UNITS` is set.
- **Local-install models** (the experimental Parakeet Ultra) load through `ParakeetLocalModelLoader.swift`, never `AsrModels.load`/`download`: FluidAudio's failed-load recovery deletes the folder and downloads stock v3 into it. A missing or broken install fails as `ParakeetLocalModelError` (local warning, not Sentry) and is never deleted.
- **Only the final transcription is pasted or saved.** The island's live words come from `LiveDictationCaptions` in `Sources/Meeting/`, fed through `DictationPreviewSampleSink`. Don't revive the old provisional-text path or dormant audio-tap branches.
- Model-init failures report through `ParakeetModelInitDiagnostics.failureContext(...)`, never raw transcript or device content.
- Telemetry key `start_plan`, not `start_profile`: the sanitizer drops keys containing `file`.

## Starting a dictation

- **Triggers.** `DictationTrigger` raw values are telemetry values; `DictationStartReadinessPolicy.hotkeyTriggerRawValues` must match them. `DictationHotkeyRouter` turns key actions into session commands carrying the real key action, and remembers a press made while the last take is finishing. Dictation is one key (`PhysicalDictationTriggerPreferences.pushToTalkBinding()`, default Right Option) with a behavior (`DictationKeyBehavior`: Hold or tap, Hold only, Tap to toggle). Under Hold or tap, a press shorter than `DictationHoldKeyTapPolicy.tapThresholdSeconds` (0.3 s, and no other key typed) is a tap and keeps the take going as a "hands-free" take; the next press stops it. Internally those takes still carry `DictationShortcutMode.handsFree`.
- **Early release.** There is exactly one producer of the early-release error: `DictationSessionController.cancelPendingDictationStartAfterEarlyRelease`, reached only when the user's own key ends a session whose mic start hasn't landed. `DictationEarlyReleasePresentationPolicy` picks wording from the actual key action and elapsed ms: a `pushToTalk` release under 250 ms gets "Hold the key while you speak"; a `handsFree` stop or a release past 250 ms keeps "Mic wasn't ready yet. Nothing was recorded." Both arrive as `trigger: physical_key`, so the trigger alone doesn't say which. Never infer the mode from stored settings; `ContextCaptureEngine` passes the real action through start and stop, and UI retries pass none. A start that exhausts `dictationRecoveryBudget` shows `microphoneTimeoutMessage` instead. The event stays `.error` (needed for the reliability record, PostHog's `reliability_failure_observed`, and Sentry), except `DictationEarlyReleaseCancelReport.forwardsToSentry` is false for a tapped Push to Talk key, which was most of Sentry issue 2J.
- **Background starts.** A start while Transcripted isn't the active app may be slower. `DictationSessionController.startDictation` takes the `DictationProcessActivity` App Nap assertion and picks a `DictationStartReadinessProfile` BEFORE any audio work; recovering after a failed background start (PR #1744) wasn't enough, so don't move that preparation after the first mic open. Issue #1743's failures were later traced to quick taps, so the assertion is preventive, not a proven fix. `NSApp.isActive` there means "frontmost when the start was requested", not "stays frontmost"; a menu start samples as foreground and then hands focus away. That's intended.
- **Short and empty takes.** `ParakeetShortAudioGate` decides what happens to very short clips; `DictationAudioRecovery` extracts a focused, gain-normalized retry segment when the first pass comes back empty with real signal. Change short-tap behavior there, not in UI controllers. `ParakeetPrewarmPolicy` gates readiness checks on mic authorization.

## Mic paths

- **Engine path:** `ParakeetEngine` plus `ParakeetAudioGraph` (the audio-graph seam: engine, serial queue, owner generation, every teardown and replacement; native calls through `ParakeetAudioGraphDriver`, owner captured before suspending and checked after, so late work never touches a successor). Fast-tested with a fake driver.
- **Pinned path** (`ParakeetPinnedMicrophone.swift`), behind `PinnedMicrophoneCapturePreferences` (on by default). Unless Apple voice processing is requested, dictation records the chosen input through Core's `PinnedMicrophoneCapture` (a Core Audio IOProc) and never creates the engine's input node, so a Bluetooth headset that is the macOS input is never pulled into call mode.
  - The one Settings "Microphone" choice (`MicrophoneChoicePreferences`) decides the mic. The meetings-only `MeetingMicrophonePreferences.usesSystemInput()` never applies to dictation: following it put dictation back on the headset mic.
  - A Bluetooth headset that is the macOS input is skipped unless the choice is "Same as macOS Sound settings". When skipped, `PinnedDictationInputPolicy` prefers the picked mic, then built-in, then wired/USB on Macs with no built-in. A picked mic beats a safe macOS input (`chosenInputAlwaysWins`, reason `userChosenInput`).
  - The recorder is used when the choice skips a Bluetooth macOS input, records a picked mic the engine can't reach, or records a plain built-in or wired mic (first audio 2-3x sooner than the engine; `PinnedDictationInputPolicy.recorderIsNeeded`). A Bluetooth headset that is itself the recorded mic, and aggregate, virtual or unknown inputs, keep the engine path.
  - Engine prewarm and readiness recovery are skipped while the macOS input is a Bluetooth headset and whenever the recorder will record (`skipsEngineWarmup`, judged on the same selection the start makes). After a fallback to the engine (`PinnedDictationWarmupState`), warmup runs again until the recorder next starts. When the engine itself records a Bluetooth macOS input (`engineRecordsBluetoothInput`), forced recovery skips warmup but replaces the dormant engine (still bound to the pre-headset route); building it never reads `inputNode`, so the headset opens only at the key press.
  - Lid closed (`MacLidState`): the MacBook mic is never picked. A pinned mic delivering only exact zeros is swapped for another input. A wake mid-dictation interrupts like the engine path. Fallback reports `pinned_microphone_fell_back_to_engine`.
  - The engine keeps one early branch each in start, stop, prewarm, readiness recovery, wake, config-change recovery, cancel, cleanup. Sample admission duplicates the engine tap's so the tap closure stays where its source-text contract tests expect it.
- `PinnedDictationSpeedPath.swift` scores takes the recorder made only for speed. Two empty takes in a row (no speech, signal with no words, or under 0.5 s from a recorder open past the 1.5 s mis-tap limit) move that mic back to the engine and the start click back to after recording starts, for the rest of the app version (`pinned_microphone_fell_back_to_engine`, stage `empty_takes`). Added after an M1 MacBook Air got no words from the 1.1.66 recorder while the engine worked. Required recorder uses (skipped Bluetooth, picked mic) are never scored. Local UserDefaults only (`pinned-dictation-speed-path`).
- **Borrowed meeting mic:** while a meeting owns the mic, dictation records relayed PCM. `ParakeetSharedMeetingMicBridge.swift` (start/finish, resume regular capture if the meeting ends first, stale-claim resolution), `SharedMeetingMicClaim.swift` (liveness probe to tell a stale claim from a live one), `SharedMeetingMicRecorder.swift` (thread-safe buffer; `MeetingCaptureBridge` delivers on its relay queue), `SharedMeetingMicLevelMeter.swift` (meters relayed buffers at `audioMeteringInterval`; the meeting's own 0.15 s level no longer feeds the island; runs on the relay queue, never the HAL thread).
- **Device selection:** `DictationInputDeviceSelectionPolicy` follows the macOS input; only the opt-in `PersistentDictationInputController` (faster Bluetooth dictation) asks for a built-in recommendation. `CoreAudioInputDeviceLookup` in `ParakeetAudioDeviceLookup.swift` does the lookups.
- **`PersistentDictationInputController`** keeps the preferred non-Bluetooth system input selected, follows reconnects, and restores prior ownership across clean or unclean exits. Startup, reconnect, preference changes and exit restoration wait for external mic capture to be idle; unknown activity reads defer writes, and skipped restoration keeps its recovery marker. Everything outside it comes in through `PersistentDictationInputSystem`; production uses `.live` (`PersistentDictationInputController+Live.swift`), tests use fakes. Its device-list listener add goes through `registerListener`, and the first topology refresh is scheduled only after that add returns.
- **`DefaultInputDeviceMonitor`** holds the one listener for the default input (state `@MainActor`; the add runs off main on `HALListenerRegistrationQueue` since at launch it's the app's first CoreAudio call). Shared by `PersistentDictationInputController`, `ParakeetEngine`/`ParakeetDeviceRecovery`, and `Sources/Meeting/MicActivityMonitor.swift`. Ordinary changes fan out immediately; a possible self-write echo uses a bounded off-main lookup, and subscribers get events in registration order with a central `isSelfWrite` flag (no observer is globally suppressed). The expected-ID/deadline token is captured at callback admission, so a late A result can't consume a newer B marker; a burst keeps at most the first event, earliest pending write echo, and latest event. `DefaultInputDeviceMonitorSupport.swift` holds the testable pieces: `DefaultInputDeviceSubscribing`, the observer registry and self-write tracker, the bounded mailbox, `HALListenerRegistrationQueue`, and `DefaultInputDeviceListenerRegistrar` (a failed add returns to idle so a later start retries; a stop while pending removes the block when the add lands).

## Engine files

- `ParakeetEngine.swift` is the core: stored state, native teardown calls, `ParakeetAVAudioEngineGraphDriver`, observers, `deinit`. Every other `Parakeet*.swift` is an extension or collaborator:
  - `ParakeetInputReadiness.swift` (prewarm, format readiness, published recovery state), `ParakeetInputRoute.swift` (device selection, route context, Bluetooth classification), `ParakeetAudioTap.swift` (installs the tap, starts the engine, voice-processing preference, mono extraction), `ParakeetRecordingStart.swift` (`startRecording`, audio watchdog, start failures, call-app mic sharing; AirPods-sensitive), `ParakeetRecordingTeardown.swift` (stop, cancel, failed-start reset, wake, idle release), `ParakeetDictationTranscription.swift` (sample timeline, draining, final transcription), `ParakeetASRInference.swift` (the ASR call with token times).
- `ParakeetDeviceRecovery.swift` detects device changes and hands real CoreAudio steps to `ParakeetDeviceRecoverySequence.swift` (closure-driven orderings: only the current generation releases latched intent, AUHAL binding errors wait and poll until superseded, a stale snapshot never commits its sample rate). Its decision tables (`ParakeetDeviceRecoveryReadinessPolicy`, `...FailurePolicy`, `...TimeoutPolicy`) live in `ParakeetStartRecordingFailurePolicy.swift`.
- `ParakeetAudioGraphSequences.swift`: user stop, route-change teardown, the restart loop, recovery snapshot lease and admission. `ParakeetAudioGraphOwnership.swift`: generation-gated owner tokens, timed-work leases, start-cancellation state. `ParakeetTimedAudioEngineWorkLimiter.swift`: the process-wide circuit. `ParakeetAudioEngineSupport.swift`: startup snapshots, retired-engine retention, listener teardown.
- `ParakeetModelLifecycle.swift` (load/download/warmup/teardown), `ParakeetModelState.swift` (shared `notLoaded/downloading/cached/loading/ready/failed` enum), `ParakeetModelInitDiagnostics.swift` (also `ParakeetLocalModelPolicy`; the install marker is re-checked after load), `ParakeetDecoderLayerCountCache.swift` (decoder layer count read once per loaded `AsrManager`).
- `ParakeetZombieEngineRecovery.swift` (+ `Sequence`): watchdog and replacement. `ParakeetSystemWakePolicy.swift`: skip teardown while borrowed-mic dictation owns the graph, else tear down and mark an active recording interrupted. `ParakeetRecoveryState.swift`: generation counter and `isRecovering` / `inputFormatReady` flags, mirrored as `@Published` and forwarded through `STTRouter`. `ParakeetInterruptionTerminal.swift`: the one way to mark a recording interrupted. `PreparedRecordingConsumer.swift`: consumes a Stop's snapshot only while its claim names the current recording. `RecordedAudioTimeline.swift`: in-memory segmented buffer across interruptions.

## Other engines and the router

- `STTRouter.swift`: the main-actor wrapper the app uses. It owns `DictationAudioLevel` and the preview sink, and holds `heldBackDictationText`.
- `WhisperEngine.swift` (advanced users): meetings send batches via `transcribeMeetingSegments` through WhisperKit's batch API with identical per-segment text; `TRANSCRIPTED_MEETING_STT_PACKING=0` turns batching off along with Parakeet packing. `WhisperCachedModelPolicy.swift` skips `WhisperKit.download` when a Transcripted-written manifest (`<whisper cache>/models/.transcripted/whisper-<variant>.json`, keyed to the app build) still matches disk; a failed cached load falls back to download-then-load once.
- `AppleSpeechEngine.swift`: macOS 26 `SpeechAnalyzer`/`SpeechTranscriber`. Apple owns and downloads per-language assets (`AssetInventory`). No language detection, so Auto means the Mac's first preferred language. Dictation transcribes Parakeet-recorded samples through `STTRouter.transcribeUsingExternalEngine`, like Whisper. Setup installs the Mac's language, then prefetches the saved meeting language. Later downloads publish only `languageDownload`, never `modelDownloadState`, so a meeting language can't make the engine look unloaded. Apple caps reserved locales (`maximumReservedLocales`); the least recently used idle one is released. A transcription failure clears that locale's installed mark. `AppleSpeechLocalePolicy.swift` maps bare language codes to Apple's per-region locales (Mac region, script-implied region such as zh-Hant to TW, home region, stable first match).
- `ExternalEngineTranscription.swift` runs a Whisper or Apple call under the recorded-transcription lease and releases it only after a thrown error is classified. `MeetingLanguageDetectionPolicy.swift` reduces WhisperKit's per-window language observations (never transcript text) to detected/uncertain/multilingual.
- `TranscriptionModelWarmupOwnership.swift`: balanced, generation-safe ownership of disposable warmup versus active dictation/meeting/import use. `ASRInferenceWaiterQueue.swift`: `@MainActor` FIFO for the ASR slot; cancellation removes only a pending waiter, and a handed-off caller must release the slot. `ModelLoadProgressWaiter.swift`: caller-owned wait on download state; finishing never cancels the shared load.
- `DictationLanguageScriptPolicy.swift` flags text that is 80%+ (4+ letters) one non-Latin script none of the person's languages use (`DictationUserLanguages.swift` gathers them, read only when flagged). `STTRouter.transcribe` holds the text in `heldBackDictationText` and reports `.otherLanguage`; the controller keeps the audio and offers Paste Anyway.

## Session and levels

- `DictationSession.swift` is the `@MainActor` engine-facing orchestrator: recovery wait loop (`waitForEngineAndStart`), model-warmup wait loop (`waitForModelAndStart`), `startDictationAudioRecording`, cancel helpers. It reports through outcome enums and injected closures, never overlay types. `DictationSessionTypes.swift` holds its class declaration and pure nested types so `run-tests.sh` can compile them without `TranscriptedAppState`. `DictationSessionController.isDictating` is the single source of truth for lifecycle; `DictationSession` deliberately has no state enum of its own (see the NOTE in that file).
- Start policies: `DictationReadinessWaitPolicy` (keep waiting, refresh readiness, or start), `DictationStartReadiness` (how a start labels itself and whether it may escalate to foreground activation; no CoreAudio timeouts on purpose, see its header and issue #1743), `DictationRecordingStartOverlayPolicy` (skip loading UI or wait for recovery, start-failure cleanup, stop routing, early-release wording).
- `DictationProcessActivity.swift`: reference-counted App Nap suppression for a session, balanced by `DictationSessionController` on `isDictating` transitions.
- **Levels.** `DictationAudioLevelMeter.swift` turns buffers into 0...1 levels with `TranscriptedConstants` floor and ceiling; `DictationAudioLevelWindow` meters every buffer a recording delivers and emits a `DictationAudioLevel` per `dictationLevelReadingInterval` (1/30 s): RMS of all audio plus the loudest buffer as `peak`. Both capture paths use it, with one main-actor hop. Keep calibration changes here, not in overlay code. `DictationAudioLevels.swift` holds the reading, owned by `STTRouter` as a `let` and kept off its `objectWillChange` (a `@Published` level re-rendered Settings and onboarding on every tick); the overlay subscribes to `readings`. The island's bars move on their own display clock (`NotchIslandLevelScroller`).
- **Preview sink.** `DictationPreviewSampleSink`: while `STTRouter.setDictationPreviewSink` has one attached, both capture paths append mono samples to it inside `pendingSamplesLock` on their capture queue. It resamples to 16 kHz with one `AVAudioConverter` kept across reads (low-passed, not the linear `AudioResampler`), and past 30 s unread drops everything unread so capture-queue work stays constant. The sink is nil unless a preview is listening; the final pass never reads it.

## Muffle ("Muffle other audio" in Settings)

Other apps keep playing, low-passed, while the dictation mic is open.

- `DictationAudioMuffler.swift`: the coordinator (called by `DictationSessionController+Muffle.swift`); runs the machine on one serial queue, performs effects on the route, and is the only part that logs.
- `DictationMuffleMachine.swift`: pure timeline (inputs, effects, virtual clock), fast-tested. `DictationMuffleFilter.swift`: TPT cutoff glide plus output gate, runs on the IO thread, fast-tested. `DictationMufflePolicy.swift` and `DictationMuffleHAL.swift`: the rules and fail-closed HAL reads.
- `DictationMuffleRoute.swift`: the Core Audio objects. Tap A (unmuted, include-list) feeds the copy through a private aggregate on the output; tap B (`.mutedWhenTapped`, include-list) in a tap-only aggregate starts only at the cut. **Never change a running tap's mute behavior**: coreaudiod restarts the IO and leaves a ~60 ms hole.
- **Bluetooth:** the muffle never opens an input device, `AVAudioEngine` or `inputNode`. It builds its aggregate only on outputs with no input streams (an unreadable count is refused). On macOS 26 AirPods expose an output-only device plus a separate mic, so muffle works on them. It also stops on an output rate change.

## Verification

```bash
bash build.sh --no-open
bash run-tests.sh
```

Manual checks: dictation starts and stops cleanly; very short takes drop, return empty, or offer transcribe as expected; final text appears after stop while the island's live words stay hover-only and are never pasted or saved; a device change doesn't strand the app or force a Bluetooth headset mic when a safer built-in exists; wake/resume doesn't strand buffered audio or leave recovery hanging.

Direct coverage is in `Tests/` as `Dictation*Tests` (audio level meter, audio recovery, input device selection, readiness wait, start readiness, session decisions, language script policy), `Parakeet*Tests` (audio graph, device recovery sequence, init diagnostics, prewarm, recovery state, short-audio gate, start-failure policy), `BluetoothRouteContractTests`, `DeviceRecoveryPolicyTests`, `RecordedAudioTimelineTests`, `SharedMeetingMicLevelMeterTests`, and `TranscriptionModelWarmupOwnershipTests`.

  - Copy lag: the copy trails the originals by ~7 ms wired but ~171 ms on AirPods (the tap delivers the mix one output latency late; confirmed by ear 2026-10-06). Opening the copy at the cut replays that much music. On lagging routes `DictationMuffleSplice` holds the gate shut for half the lag and swells the copy in over the other half, reaching full level where the originals stopped, so the music eases into muffled (the filter jumps to its target while held) with no quiet-moment wait at the cut. A full-lag hold (silence) was noticeable; the swell was the owner's pick by ear.
