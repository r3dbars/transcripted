# TranscriptedCore

The reusable meeting transcription library. The app links it as a prebuilt library; `Sources/Meeting/` is the one module that uses all of it. It also builds and tests as a standalone Swift package through the root `Package.swift`. Repo-wide rules are in the root `AGENTS.md`.

## Module card

`Core` in `.agents/modules.json`.

- **Owns:** meeting capture (mic + system audio), the transcription pipeline and queue, diarization, the speaker database and naming, transcript save and formatting.
- **Public surface:** only `public` declarations count, in three tiers (lists in `.agents/modules.json`):
  - `core-vocab`, which any app module may name: logging, `PrivacyTextRedactor`, `SupersessionEpoch`, `ClaimSlot`, `DateFormattingHelper`, `TranscriptFrontmatter*`, `TranscriptFileRewrite`, `AudioResampler`, `TranscriptionLanguage*`, `SpeakerProfile`, `SpeakerNaming*`, `NameSource`.
  - `mic-primitives`, for Speech: `PinnedMicrophoneCapture*`, `MicrophoneDownmix`, `MacLidState`, `AudioTapInstallGuard`, `AudioInputTapTeardownPolicy`, `ModelDownloadService`.
  - `core-engine`, everything else, for Meeting.
- **May depend on:** nothing in the app; the compiler enforces it. App modules outside Meeting reach `core-engine` behavior through Meeting, never by naming its types.
- **Entry points:** `Audio` (capture), `TranscriptionTaskManager` (queue), `Transcription` (pipeline), `SpeakerDatabase`.
- **Tests:** `swift test` (five SPM targets: `AudioTests`, `SpeakerTests`, `PipelineTests`, `StorageTests`, `UtilitiesTests` under `Tests/TranscriptedCoreTests/`; `Tests/README.md` shows how to scope a loop), `bash run-integration-smoke.sh`. After any change here: `bash build-deps.sh --force`, then `bash build.sh --no-open`, then `bash run-tests.sh`. Changing protocols, `AppServices`, `Package.swift` or public models: also run `swift test` so the standalone boundary is checked.

## Editing rules

- No app-shell UI types in here. Prefer injected paths, providers and protocol seams over `Bundle.main`, app globals or home-directory assumptions. A dependency hosts need must be injectable at the Core boundary.
- CoreAudio real-time callbacks: no I/O, locks, allocations or ObjC calls. Deep-copy buffers before any async hop.
- `Audio+CaptureLifecycle.swift` (stop ordering) and `Audio+MeetingInputGraph.swift` (the AirPods-sensitive engine and `inputNode` touch) are the riskiest code in Core. Read the whole file first and add no new responsibility to them.
- Keep `AudioPipelineDiagnosticsSnapshot` privacy-safe: bucketed device classes, rates, channel counts and recovery state only. Never raw device names, transcript text, titles, paths or audio.
- Keep app-specific permission UX outside this directory.

## Threading

- `Audio` and most `Audio/*` helpers are not `@MainActor`; they run on audio and background threads. `TranscriptionTaskManager`, `Transcription` and many services are `@MainActor ObservableObject`. Heavy pipeline work leaves the main actor through `nonisolated` async helpers in `TranscriptionPipelineRunner.swift`.
- PCM write admission uses lock-free atomics (`PCMBufferBackpressureGate`). Host fan-out and file writes use separate bounded queues, so a slow disk can't delay borrowed-mic dictation. Stop drains both admitted tails before the app clears the host consumer, and detaches exact-generation writers only from their serial queue barriers.
- The mic tap keeps delivering until its background teardown, so `stop()` holds mic admission in `finishing` from before the generation advances until `closeMicrophone`. `MicStopTailHandoffTests` pins that order.
- Live meeting preview audio (`Audio+LivePCM.swift`, `LiveMeetingPCMDelivery.swift`) is optional and lossy on its own bounded queue. Overflow drops preview buffers only; the saved recording is never affected.

## Layout

Run `find Sources/TranscriptedCore -name '*.swift'` for the live list. By folder:

- `ObjCSupport/` is the `TranscriptedObjCSupport` target (`TRNObjCExceptionCatcher`), its own SPM target. It lives here so the deps staleness digest and CI cache key cover it. Core imports it `@_implementationOnly`; keep it that way so the CLI and other prebuilt-Core consumers need no extra `-I`. `build-deps.sh` copies its `include/` into `deps-modules/`.
- `Audio/` is capture. The `Audio` class is split by concern into `Audio+*.swift` (lifecycle, mic graph, voice processing, recording health, sleep/wake, artifacts, mic and system writes, pinned mic, unheard-playback). Support types: `AudioCaptureStartState`, `MeetingInputDeviceLookup` (device lookup and built-in fallback selection), `MeetingMicGraphStartSequence`, `MeetingInputDeviceSelectionPolicy`, `MeetingRecordingJournal`, `MicRecordingFileMerger` and `MicRecordingSegment`, `MicOnlySilentSystemTrack`, `PinnedMicrophoneCapture` with its ring, `RealtimeAGC`, `QuietMicAttenuationDetector`, `AudioSignalRecovery`, `FailedRecordingSignalProbe`, `WAVHeaderRepair`, and the system-audio side: `SystemAudioCaptureEngine` (backend protocol), `CoreAudioSystemAudioCapture` (+ ring, drain cadence, `SystemAudioSilenceWatch`, `SystemAudioTapFailure`) and the legacy `SCKAudioCapture`.
- `Logging/` is `AppLogger`, `FileLogger`, `LogTailTrimmer` (truncate-in-place rotation, also used by the app's `AppLogSink`), `PrivacyTextRedactor`, `LogPrivacySanitizer`. How these differ from `Sources/Observability/AppLogSink.swift`: `docs/observability.md`.
- `Models/` holds the public data types (utterances and results, pipeline errors, display status, failed transcriptions, speaker mapping, recording health, transcription language).
- `Pipeline/` is orchestration. `TranscriptionTaskManager` is the single-flight queue; its extensions cover start, failure classification, failed-audio retention, orphaned-recording recovery, retry and cleanup paths. It keeps `tasks` private behind `beginTaskLifecycle`, `forgetTaskLifecycle` and `lifecycleOwnedAudioPaths`. `TranscriptionPipelineRunner` runs the pipeline off the main actor. `Transcription` plus `TranscriptionPipeline+*.swift` are the stages: multichannel, mic-only, mic diarization, last-chance sweep, system-speaker identity, track loading. Also `SpeechSegmentPacking`, `TranscriptionJobActivity` (holds off App Nap and idle sleep after Stop), `MeetingPipelineTimings`, `PipelineFailureDisplayCopy`.
- `Protocols/` are the host-injected seams: `SpeechToTextEngine`, `DiarizationEngine`, `SpeakerStore`, `TranscriptNotifier`, `StatsStore`, `ImportedTranscriptionRecoverySession`.
- `Services/` is `AppServices` (DI), `CoreStoragePaths`, `ModelBundleProvider`, `ModelDownloadService`, the diarization stack (`DiarizationService`, `DiarizationBackend`, `NemotronDiarizationRunner`, `NemotronTurnBuilder`, `FluidAudioCompatibility`), `RecordingValidator`, `FailedTranscriptionManager`, and `CaptureLibraryPathSafety` (a synced copy of the path checks also in `Sources/Support/` and `Tools/TranscriptedCaptureKit/`; `scripts/dev/check-synced-copies.py` guards it).
- `Speaker/` is the speaker stack. `SpeakerDatabase` is instance-based and injected through `AppServices`; there is no `.shared`. Groups: stores (profiles, confirmations, exemplars, negative exemplars, match outcomes), embedders and matching, policies, the naming coordinator and `SpeakerIdentityMutationService` (the single write path for name and merge changes across the DB and saved transcripts), `RetroactiveSpeakerUpdater` (transcript rewrites), `SpeakerSeparation`, and the voiceprint migration set (below). Recognition metrics: `docs/speaker-recognition-metrics.md`.
- `Stats/` is the recording stats database. `Storage/` is `TranscriptSaver`, `TranscriptFormatter`, `TranscriptFrontmatter`, `TranscriptFileRewrite` (rewrites a saved transcript in place without resetting its Created date), `RecordingAudioArchiver`, and `SQLiteHandle` (shared open/permission/pragma bootstrap). `Utilities/` is date formatting, file permissions, `SupersessionEpoch`, `LabKnobOverrides`.

## Seams for embedders

- `CoreStoragePaths` redirects all persisted output away from the standalone defaults. `ModelBundleProvider` overrides where offline model bundles resolve. `AppServices` is the DI container over protocol-typed STT, diarization and speaker-store dependencies. `TranscriptNotifier` is the optional saved/failure callback channel.
- `Transcription.transcribeAudioFile(at:languageSelection:onProgress:)` is file-only diarization, transcription and speaker matching. It reuses the meeting pipeline and returns `TranscriptionResult` without capturing, saving, archiving or deleting input audio. Calls on one instance must be serialized. Injected engines control model downloads, and the injected `SpeakerStore` may be mutated; pass an isolated snapshot store to leave the real speaker DB alone.
- `TranscriptionTaskManager` is the host-facing queue, including imported-audio jobs and optional local-speaker mic diarization. Imported audio goes through the same pipeline primitives as live captures, so formatting, stats, naming and retry stay aligned.
- `ImportedTranscriptionRecoverySession` keeps app-owned imported-audio recovery alive across Core's transcript commit and deferred speaker-review scratch cleanup. Core must durably prepare cleanup before deleting scratch and reports completion only after deletion. No untyped terminal callback, no parallel ownership map.

## Environment variables Core reads

- `TRANSCRIPTED_LAB_KNOBS_FILE` is read once per process by `Utilities/LabKnobOverrides.swift`. It names a JSON object of hill-climb knob overrides. Unset (every normal run) means no file I/O. Only ids in `LabKnobOverrides.knownIDs` are honored: the four `diarization.*` knobs in `Services/DiarizationService.swift` and the four `speaker.cluster.*` thresholds in `Speaker/SpeakerEmbeddingThresholds.swift`. Anything else is warned about on stderr (ids only) and dropped. A new knob needs the call site, the id in `knownIDs`, and an entry in `config/hillclimb/knobs.json`. It is the only env var that changes pipeline math; don't add more unless a host seam can't do the job.
- Lab-only, diarization: `TRANSCRIPTED_NEMOTRON_PRESET` and `TRANSCRIPTED_NEMOTRON_EMBEDDER=online` (below).

## Diarization backends

`DiarizationService(bundleProvider:segmentEmbedder:backend:allowDownload:)` runs one of two FluidAudio diarizers, picked by `DiarizationBackend`. The init default is `.pyannote`; the app and every CLI path (`import-audio`, `diarize`, `batch`) default to `.nemotron` via `DiarizationBackend.hostDefault` / `effective` (host-side switch: `Sources/Support/DiarizationBackendPreferences.swift`). `allowDownload` defaults to true; CLI `--no-download` sets it false so a Nemotron load failure cannot download pyannote. The public API is the same for both. `activeRunDescriptor` (`DiarizationRunDescriptor`: `activeBackend` plus the voiceprint embedder id) is read right before diarizing and lands in `TranscriptionResult.diarization`, which the formatter writes as `diarization_engine` / `voiceprint_model` (`none` and no voiceprint key when no diarizer ran).

- `.pyannote`: `OfflineDiarizerManager` (community-1 segmentation + WeSpeaker + VBx) with `FluidAudioCompatibility.tunedOfflineDiarizerConfig()`. That undoes FluidAudio 0.17's two clustering changes: the threshold is now a Euclidean distance (cosine 0.6 is passed as sqrt(0.8)), and constrained assignment is off.
- `FluidAudioCompatibility.keepUnpinnedDiarizerCaches()` runs in `DiarizationService.init`. FluidAudio 0.17 pins the `speaker-diarization-coreml` repo to one commit and deletes any cache without a matching revision marker, which every 0.15.x-era cache lacks. Resolving at `main` keeps them valid. Anything that loads diarizer models without `DiarizationService` must call it first.
- `.nemotron`: NVIDIA Nemotron 3 Diarization. If its models fail to load, `performOfflineInitialization` loads pyannote and `activeBackend` says so, unless `allowDownload` is false and no local pyannote bundle is present — then it keeps the Nemotron error. `cleanup()` resets it so the next initialize retries Nemotron. `NemotronDiarizationRunner` loads one `Nemotron3Config` preset (`fast128` default; `TRANSCRIPTED_NEMOTRON_PRESET` names another, e.g. `fast32` or `offline`, which runs on CPU+GPU because it fails the ANE compiler). It runs a fresh non-thread-safe `Nemotron3Diarizer` per call on a private serial queue, fed `DiarizationBackend.nemotronSliceSeconds` slices through the streaming API (not `processComplete`) so the whole-recording mel and padded copy are never held. Bundled copy: `bundleProvider("nemotron-diarizer-models")`, flat layout; otherwise FluidAudio downloads into `FluidAudio/Models/nemotron-3-diarization/` (`monolithic/v2/` on a provisioned install, only treated as local when `.fluidaudio-nemotron3-weights` matches `DiarizationBackend.nemotronCacheWeightsVersion` and the resolved preset's `.mlmodelc` is present).
- `NemotronTurnBuilder` (pure, unit-tested) turns 10 ms per-speaker probabilities into turns: argmax of speakers >= 0.5 per frame, same-speaker silence < 0.2874 s bridged, turns < 0.25 s dropped, slots renumbered by first appearance. Turns never overlap, because the pipeline transcribes each segment separately. `speakerId`s are 1-based like pyannote's `S1…`; `qualityScore` is the turn's mean winning probability.
- Nemotron emits no voiceprints. Each turn is embedded with the injected `SpeakerSegmentEmbedder` when there is one, otherwise with `FluidOfflineWeSpeakerSegmentEmbedder`: the pyannote path's own `FBank.mlmodelc` + `Embedding.mlmodelc`, run on a real 10 s window of meeting audio with the weight mask on only over the turn. Never zero-pad; padding skews the fbank normalization. Same space as the saved people, so it shares `speakers.sqlite` and the `.weSpeaker` thresholds. `TRANSCRIPTED_NEMOTRON_EMBEDDER=online` switches to `FluidWeSpeakerSegmentEmbedder` (own DB file).
- FluidAudio's version lives in one place: `FLUID_AUDIO_VERSION` in `scripts/entrypoints/build-deps.sh` (`check-known-traps.py` compares it with Tools packages). build-deps checks the source out into a temp dir and deletes it, so read FluidAudio's code from the SwiftPM cache: `git -C ~/Library/Caches/org.swift.swiftpm/repositories/FluidAudio-* show v<version>:<path>`. Don't trust a `.build/checkouts/FluidAudio` in another checkout; it is often older.

## Voiceprints and speaker thresholds

- `ReDimNet2Embedder` is the default voiceprint, on the generic `CoreMLSpeakerSegmentEmbedder`: multifunction 1/2/4/8 s fp16 on CPU+GPU, 8 s windows. Each length loads under its own lock in `CoreMLVoiceprintFunctionRouter` and is released 60 s after the last call. GPU memory (about 370 MB for 8 s, 470-540 MB for all four) arrives with the first predict, not the load. The pipeline reloads all four (load only) in the background at job start and diarize start; `DiarizationService` warms only the lengths a meeting needs, right before re-embedding (`SpeakerSegmentLengthPrewarming`). Every voiceprint predict and every re-embedded turn runs in its own `autoreleasepool` so Core ML arrays don't pile up across a meeting.
- `ERes2NetEmbedder` is the older on-device voiceprint. `BackgroundLoadingSpeakerSegmentEmbedder` knows id, size and thresholds up front and loads its model on a background queue the first time anything waits. A failed load or mismatched model makes `embed` return nil, so a model-keyed DB never receives another model's vectors.
- `SpeakerEmbeddingThresholds` holds every cosine bar the speaker stack compares a voiceprint against (match floors, clustering, and the identity bars: match guards, negative veto, write-back, cluster link, exemplar, naming ladder, confidence, duplicate and separation merge). A new model's come from a calibration JSON via `SpeakerEmbeddingThresholds.load(contentsOf:)`. The pipeline reads the diarizer's `activeSpeakerThresholds`; `SpeakerDatabase(path:thresholds:)` carries the same set for its own decisions, so a host builds it from the active embedder. Constants like `SpeakerNamingPolicy.autoAcceptSimilarityThreshold` are the WeSpeaker values, for callers with no model in hand.
- Which voiceprint model and speaker database a run uses is one pure rule, `SpeakerVoiceprintSelection` (preference, `TRANSCRIPTED_SPEAKER_EMBEDDER`, ReDimNet2 default, missing/failed-load fallback to WeSpeaker and `speakers.sqlite`). The app's `SpeakerEmbedderFactory` and the CLI's `import-audio` both use it; `Tests/Fixtures/speaker-voiceprint-resolution.json` is asserted by Core, the app and the CLI. `SpeakerNamingPolicy.silentNamingBlockers` explains a withheld silent name and must stay equal to `shouldAutoAccept` (grid test).
- Confirmation meetings: the ledger counts one row per (profile, meeting id). An imported file's transcript is aliased at commit (`speaker_confirmation_meeting_aliases`, `SpeakerConfirmationMeetingID`) to an id derived from the file's content hash, and `recordUserConfirmations` resolves every write through it, so re-imports, re-transcriptions, Settings and merges count one recording once.
- Voiceprint model switch: `SpeakerVoiceprintMigration` (actor) carries every user-named person from one model's DB to another's under the same UUID, name, counts and confirmation ledger, re-embedding saved review clips and retained meeting audio. The app runs it at launch via `Sources/Meeting/MeetingVoiceprintMigrationLaunch.swift`. `SpeakerVoiceprintMigrationGate` (`@MainActor`) starts one run per launch, stays closed until it ends, and every speaker-database writer must `await waitUntilOpen()` first. A failure opens it with a reason code only, and the next launch runs again. The source DB is read through `SpeakerVoiceprintSourceSnapshot` (SQLite backup copy); never open the source file with `SpeakerDatabase`. The self-agreement gate holds confirmations back until `recordUserConfirmations` releases them for the profiles it confirms.

## Audio backend notes

- `Audio` reaches system audio through `SystemAudioCaptureEngine`; tests inject stubs there. `CoreAudioSystemAudioCapture` uses Core Audio process taps (System Audio Recording Only permission). `SCKAudioCapture` stays for its regression tests, not as a permission-expanding fallback; it still enumerates shareable screen content, so audio-only output doesn't prove the narrower permission (`experiments/audio-only-probe` records that proof). `SCKAudioCapture` owns one bounded mid-recording restart, publishes `reconnecting` before it and `failed` only when recovery fails; don't restart from amplitude silence. Its stream identity, generation and phase share one ownership lock so `stop`/`stopSync` either win before a start or own the exact stream until its stop callback.
- The tap records the last HAL step that refused and its OSStatus (`SystemAudioTapFailure`), reported as `system_tap_step` / `system_tap_status`. Keep both values codes, never error text.
- `SystemAudioSilenceWatch` is the tap's digital-silence watch. It arms at start, after a wake, after a stall or format rebuild, and on default-output change. It rebuilds the tap a bounded number of times, only while another process is running audio output, then sets `isNotHearingPlayback` (read lock-free via `Audio.isSystemAudioNotHearingPlayback`) so the host can warn. Zeros on a quiet Mac never trigger it. A wake gets one silent-tap rebuild, not more: a call app keeps output running while the far end is quiet, so extra rebuilds cut real audio. If signal returns on the same tap, the report is cleared; only signal that needed a non-wake rebuild or an output move sets `didLosePlayback` (`Audio.systemAudioDidLosePlayback`), which keeps a saved meeting degraded. A sleep ends an open report; a watch never expires while one is open.
- Ring overflow: `CoreAudioSystemAudioCapture` reconnects (up to 3 per recording), pads the dropped span (`lostFrames`) and reports `.fellBehind`, which holds writes like a reconnect but isn't counted as a device switch.
- `AudioCaptureStartState` is the readiness policy: capture doesn't report success until mic recording runs and the system-audio file exists.
- Mic-only by choice: a host that sets `Audio.capturesSystemAudio = false` before `start()` ("Record Just My Mic") gets no tap; readiness waits on the mic alone (`requiresSystemAudio: false`). Sleep/wake, health grading, late tap errors and diagnostics must ignore the previous meeting's tap, so read it through `recordingSystemAudioCapture`, never `systemAudioCapture`. The journal records `micOnlyByChoice`. At stop the host writes `MicOnlySilentSystemTrack` (sparse silent WAV at the mic's rate and length) to keep the two-track shape, and marks health `markingSystemAudioSkippedByChoice()`: the formatter writes `mic_only: true`, and `markingSystemAudioMissing()` becomes a no-op so a deliberate choice is never saved as degraded. Failed rows carry `micOnlyByChoice`; `retryFailedTranscription` writes a missing silent track and `retryHealthInfo(for:)` keeps the marker.
- Wake recovery snapshots the recording generation and exact system-audio backend when the wake notification arrives. Both settle delays and the handoff after native mic recovery must reject a stopped or replaced session, so an old wake can't restart a newer meeting or consume its sleep marker.
- Mic selection (`MeetingInputDeviceSelectionPolicy`): by default avoids a Bluetooth headset input when a built-in fallback exists, so call-mode downgrades don't get worse. A host may set `Audio.meetingInputDeviceSelectionMode = .preserveDefault` before `start()` (the app does when "Use Mac-selected microphone" is on without the pinned recorder, or when the recorder is on and the Settings choice is "Same as macOS Sound settings", `MeetingMicrophonePreferences.recordsMacOSInput`). In `.automatic`, `Audio.meetingPreferredInputDeviceUID` names a specific mic (reason `userChosenInput`), never a Bluetooth headset or a closed MacBook's own mic. If that first attempt was a meeting start on the pick and not a voice-processing fallback, the retry drops the pick for this recording (`dropMeetingPreferredInputDeviceForCurrentRecording`) so a stubborn pick never costs the meeting; mid-meeting recovery keeps it. The mode is captured per recording and survives graph retries. A rejected explicit device bind fails the attempt and uses the bounded retry instead of recording from the previous mic. If the pinned mic fails to start or recover (or never delivers a frame), the graph falls back to the best built-in (`builtInFallbackAfterFailure`). With the lid closed (`MacLidState`), the MacBook's own mic (`isLidMicrophone`, not the headphone-jack mic) is excluded from every built-in pick, since it records silence without failing, for both backends. Selection never changes the macOS input or output setting.
- Mic recovery: an `AVAudioEngineConfigurationChange` observer (`MicEngineConfigurationChangePolicy`) restarts a stopped meeting mic about 0.25 s after a route change, within the watchdog's attempt limit. Device-change recovery first restarts the existing engine in place when it is still bound to the pinned non-Bluetooth mic (`MicInPlaceRestartPolicy`), because a fresh `AVAudioEngine` input node touches the macOS default input and can flip AirPods into call mode. A failed recovery isn't terminal: the watchdog retries, stopping only after `maxRecoveryAttempts` in a row. Recovery segments are registered before their first frame so Stop keeps them; a header-only segment merges as empty. `MeetingMicGraphStartSequence` fixes the engine-path order: settle the route, size the mic file from the settled graph, then recheck the format and install the tap under the graph lock (the AirPods 24 kHz flip guard). Every `installTap` goes through `AudioTapInstallGuard`, which turns the ObjC exception on a format mismatch into a failed attempt (domain "Audio", code 12).
- `PinnedMicrophoneCapture` records one input `AudioDeviceID` through a Core Audio IOProc. It exists because a fresh `AVAudioEngine.inputNode` binds the macOS default input before `setDeviceID` can move it. It is used when the host sets `Audio.usesPinnedMicrophoneCapture` (off by default; the app's `PinnedMicrophoneCapturePreferences`), Apple voice processing is off, and the selection skips a Bluetooth default (`pinnedRecorderIsNeeded`). `Audio+PinnedMicrophone.swift` wires it to the same selection policy and `handleMicBuffer` sink, no engine graph. Behavior to preserve:
  - One recording format (later device formats are resampled); holes from HAL timestamps are padded with silence, not written as recovery segments; stall or format change restarts in place on the same device.
  - HAL format notifications are debounced (one rebuild 0.3 s after the last, not counted against the restart budget while the format is still changing). A rebuild that throws on a live device retries at 1/2/4/8 s before `.failed`. Format and stall checks pause while sleep is pending and for 3 s after wake.
  - Silence pads are paced (at most 1 s or 1 MB per tick) and delivered in order ahead of later audio. Ring storage is capped at 16 MB; a device that can't fit fails `prepare()` so the owner uses the engine.
  - An unbroken 1.5 s of exact zeros reports `.silentInput` once per device. A lost device is re-picked without the dead one, with a few retries; if the macOS default (even a Bluetooth headset) is the only mic left, the meeting moves to it rather than losing the user's voice. A silent device is swapped only when it is a lid mic and the lid is closed, so a deliberately muted mic keeps recording.
  - `Audio.isRecordingThroughPinnedMicrophone` tells the host not to offer the in-meeting voice-processing boost, which needs the engine path.
- `RealtimeAGC` is the default meeting-mic cleanup: it avoids Apple voice processing's playback ducking while boosting quiet WebRTC-contended captures and gating idle USB-mic noise. Hosts can disable it for raw mic capture.
- `AudioSignalRecovery` does peak / RMS / active-ratio checks and gain-normalized recovery clips. `hasSpeechLikeModulation` and `normalizeForSpeech(ignoringSpikes:)` serve the last-chance pass, which silence-splits diarizer-dependent tracks (the call side of an empty meeting, a split-mode mic with no words) before "No speech found". The normal pass keeps plain-peak gain and drops sub-second system segments until a corpus A/B says otherwise.
- `FailedRecordingSignalProbe` decides whether a failed meeting still has audio worth retrying, streaming in bounded windows. Its result is three-valued: `.absent` only after the entire artifact was examined; anything unreadable or past the scan budget is `.inconclusive`. Hosts must never suppress a retry affordance on `.inconclusive`; a wrong silence verdict hides recoverable audio.
- `MeetingRecordingJournalStore` persists in-progress journals for launch recovery. Mutations are scoped to the session token from `begin(...)`, so late stop-path writes can't corrupt a newer recording's journal.

## Storage and format

Standalone `TranscriptedCore.default` paths, under `~/Library/Application Support/Transcripted/`: `captures/meetings/` (captures), `state/` (databases, failed queue), `tmp/recordings/` (clips, raw audio scratch), `logs/`. The app injects its own `CoreStoragePaths` so the capture folder follows the selected capture library. Full map: `docs/storage-paths.md`.

`TranscriptSaver.saveTranscript(...)` writes the Markdown transcript with YAML speaker metadata and recording-health fields (`capture_quality`, `audio_gaps`, `device_switches`). The format (frontmatter keys, `format_version` / `transcript_style`, both body grammars, the save, summary-injection and restyle lifecycle) is specified in `docs/capture-format.md`; keep that in sync with formatter changes, and keep new frontmatter keys flat (the shared parser skips indented lines).

The standalone CLI and MCP tools parse the same Markdown through a dependency-free mirror in `Tools/TranscriptedCaptureKit` (it intentionally doesn't link Core). If `TranscriptFormatter` or `TranscriptFrontmatter` changes the written format, update the kit's parsers and tests in the same change.
